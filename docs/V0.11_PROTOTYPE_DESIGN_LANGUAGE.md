# v0.11 prototype — design language comparison

Comparing the local v0.11 EW300 prototype against the v0.10.0 production app.

## Unchanged

- My DAC shell: the same device header, EQ / DEVICE secondary tabs, Refresh action, and section
  order.
- Shared components: DacEqEditorScreen, the response graph, review screen, Apply flow, capture,
  Save, and Reset all remain the production widgets.
- Typography, spacing, card and value-row presentation, and semantics follow the production
  screens; the instrumented suites that exercise these screens pass unchanged.
- Settings: Output behaviour, Available outputs, Default EQ target, Export folder, and About keep
  the production layout. The SIMGOT EW300 DSP row is a normal hardware row with a Direct Flash
  switch, identical in shape to the FiiO JA11 and TRN Black Pearl rows.

## Changed for the prototype

- The parity research panel is gone from Settings in the product build. It remains compiled only
  in the local engineering variant, so the normal flow has no numbered setup block.
- The My EQs list carries one status line naming the Flash prerequisite when the active output is
  a hardware DAC; it appears only then, and it is a single line rather than a card.
- The EQ tab no longer offers shelf listening controls in the product build; the section is
  engineering-only.

## Copy rules applied

- Every unavailable action names the exact missing prerequisite instead of showing a dead control:
  "Direct Flash is off. Enable it in Settings → SIMGOT EW300 DSP." and
  "SIMGOT EW300 DSP is not connected. Connect it in My DAC."
- Capability claims match evidence: sample rate is shown as the UAC1 endpoint value, UAC mode is
  read-only, headset control is reported as having no disable control, and firmware is shown as not
  read when it has not been read.
- No switch or row exists for a chip-limited feature.

## Accessibility

- The response graph keeps its descriptive content description.
- Button labels are action-first ("Set Flat", "Save EQ and output gain", "Flash"), so the Flash row
  and the engineering controls cannot be confused by label alone.
- The single-line Flash status uses the theme's primary or error colour together with the text, not
  colour alone.


## v0.11 UX correction (candidate 12974c73)

Applied after the first Pixel-qualified build, from the owner's review:

- The DEVICE page now uses the JA11 section rhythm exactly: DeviceOperationStatusHeader, then
  Audio, USB & System, and About. Section labels, row height, typography, and value alignment come
  from the shared DacDeviceStatus components, which are now internal so both device pages render the
  same widgets.
- One volume concept: a single Device volume row (0–60). The duplicate Output gain row is gone.
- Rows that would say Unknown or Not read are not rendered. Startup settings appears only when the
  saved state is known; Firmware appears only when it has been read.
- About carries identity plus one plain limitation line. Per-row provenance captions were removed
  because they repeated "Known device capability" on every line.
- The microphone section is gone. The device accepts a mute request and the value verifies, but no
  capture path reaches it from this Pixel and the owner heard no difference, so the control cannot
  be called Live or Muted.
- Engineering language (parity panel, shelf A/B controls, experimental features, raw descriptor
  copy) does not appear in the product build.
