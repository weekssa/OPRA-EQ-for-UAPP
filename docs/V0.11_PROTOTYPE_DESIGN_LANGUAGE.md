# v0.11 prototype — design language comparison

Comparing the local v0.11 EW300 prototype against the v0.10.0 production app.

## Unchanged

- My DAC shell: the same device header, EQ / DEVICE secondary tabs, Refresh action, and section
  order.
- Shared components: DacEqEditorScreen, the response graph, review screen, Apply flow, capture,
  Save, and Reset all remain the production widgets.
- Typography, spacing, card and value-row presentation, and semantics follow the production
  screens; the instrumented suites that exercise these screens pass unchanged.
- Settings: Output behaviour, Available outputs, Default EQ target, Export folder, and About keep
  the production layout. The SIMGOT EW300 DSP row is a normal hardware row with a Direct Flash
  switch, identical in shape to the FiiO JA11 and TRN Black Pearl rows.

## Changed for the prototype

- The parity research panel is gone from Settings in the product build. It remains compiled only
  in the local engineering variant, so the normal flow has no numbered setup block.
- The My EQs list carries one status line naming the Flash prerequisite when the active output is
  a hardware DAC; it appears only then, and it is a single line rather than a card.
- The EQ tab no longer offers shelf listening controls in the product build; the section is
  engineering-only.

## Copy rules applied

- Every unavailable action names the exact missing prerequisite instead of showing a dead control:
  "Direct Flash is off. Enable it in Settings → SIMGOT EW300 DSP." and
  "SIMGOT EW300 DSP is not connected. Connect it in My DAC."
- Capability claims match evidence: sample rate is shown as the UAC1 endpoint value, UAC mode is
  read-only, headset control is reported as having no disable control, and firmware is shown as not
  read when it has not been read.
- No switch or row exists for a chip-limited feature.

## Accessibility

- The response graph keeps its descriptive content description.
- Button labels are action-first ("Set Flat", "Save EQ and output gain", "Flash"), so the Flash row
  and the engineering controls cannot be confused by label alone.
- The single-line Flash status uses the theme's primary or error colour together with the text, not
  colour alone.


## v0.11 UX correction (candidate 12974c73)

Applied after the first Pixel-qualified build, from the owner's review:

- The DEVICE page now uses the JA11 section rhythm exactly: DeviceOperationStatusHeader, then
  Audio, USB & System, and About. Section labels, row height, typography, and value alignment come
  from the shared DacDeviceStatus components, which are now internal so both device pages render the
  same widgets.
- One volume concept: a single Device volume row (0–60). The duplicate Output gain row is gone.
- Rows that would say Unknown or Not read are not rendered. Startup settings appears only when the
  saved state is known; Firmware appears only when it has been read.
- About carries identity plus one plain limitation line. Per-row provenance captions were removed
  because they repeated "Known device capability" on every line.
- The microphone section is gone. The device accepts a mute request and the value verifies, but no
  capture path reaches it from this Pixel and the owner heard no difference, so the control cannot
  be called Live or Muted.
- Engineering language (parity panel, shelf A/B controls, experimental features, raw descriptor
  copy) does not appear in the product build.

Screenshots: docs/screenshots/v011/{device-top,about-expanded,device-bottom,limitations}.png, all
from this candidate at 360 dp width; device-bottom uses a 360×360 viewport because the page fits
otherwise.


## Polish pass (candidate 1995927d)

- Startup settings now matches JA11: "Not saved" carries a Save action; "Saved" does not. An
  unknown state still renders no row.
- USB Audio Class moved to About ("USB audio class"). It is a fixed property of the device, so
  presenting it in the USB & System section implied a setting that does not exist. USB & System now
  holds only the read-only current sample rate.
- Copy shortened to one line per concept: the volume dialog, the Settings Direct Flash help, and the
  EW300 output subtitle. Labels stay sentence case and every row keeps a single action.
- Consistency: both device pages now render through the same shared rows and section titles, so the
  EW300 reads with the same rhythm as the JA11.


## Settings v2 (candidate 1e97db8e)

Five groups: EQ target, Outputs, Library, Appearance, About. One trailing control per row, short
device subtitles ("5-band Peak PEQ"), Direct Flash on its own indented switch row, a Default target
picker behind Change, and a Library group where folder, hidden EQs and catalog are value rows.

Removed: five stacked paragraphs around Output behaviour, both Available-outputs intros, the duplicate
default-target list, the folder and catalog explanation paragraphs, the update-channel paragraph, and
every link description. Root copy went from 867 to 616 words (-29%) across 93 to 81 strings.


## Settings v2 accessibility and density check

Captured on emulator-5554 at 360 dp wide (1080x2400, density 480) with font scale 1.0, 1.3 and 2.0:
docs/screenshots/v011/settings-360dp-font{100,130,200}.png.

- At 1.0 and 1.3 the five groups fit without clipping; values stay on one line.
- At 2.0 labels wrap to two lines ("Use a connected DAC / when available."), the Default target value
  wraps to three lines, and the Change action keeps a 48 dp target without truncation. No row overlaps
  and nothing scrolls horizontally.
- The DAC status card remains at the top of My EQs, EQ Library and Settings: ten instrumented tests
  navigate to My DAC through its "Open My DAC" label, and the nav bar only exposes My DAC when a DAC
  is recognized. Removing the card is therefore a navigation change with a test migration, not a
  Settings-only deletion; it was attempted, verified visually, and reverted to keep the suite honest.


## Stateful context bar (shipped)

Target row first, then a device block whose action follows the state: Connect when the target DAC is
attached and ready (or retrying permission / a failed session), Open Settings when Direct Flash is
off, Open My DAC when the session is live or the device is absent. The body is a separate focusable
target from the trailing 48 dp button, both with state-bearing content descriptions. Status copy is
one line each: Not connected, Allow USB access, Connection issue, No DAC attached, Direct Flash off,
and the existing connected states. No bar on Settings.

### Display anchor

The bar keeps speaking for the last hardware target after Automatic output resolution hands the EQ
target back to an app, so unplugging shows "No DAC attached" with Open My DAC rather than silently
dropping the block. The anchor is retired only by an explicit non-hardware pick in the target picker.
