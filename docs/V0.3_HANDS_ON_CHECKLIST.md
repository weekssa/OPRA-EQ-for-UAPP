# EQ Library v0.3 Hands-On Validation

Use the latest **signed beta** artifact from `v0.3-release-polish` for the final release-polish pass. Do not use an ordinary debug APK for the upgrade test.

The full checklist below records the already-passed v0.3 foundation/Black Pearl qualification. For the final post-merge UI/catalog polish, run the focused addendum immediately below plus a quick UAPP/Black Pearl smoke check; repeat the deeper hardware sections only if the final diff unexpectedly touches device/DSP behavior.

## Final release-polish addendum

Use the final exact-head signed candidate only. Start each batch-selection screen with no rows selected unless the checklist explicitly says otherwise.

1. **Back hierarchy:** From My EQs → headphone → Manage preset selection, use Android Back repeatedly. Clean editor → headphone detail → My EQs root must occur before the app exits. With unsaved editor changes, Back must show Discard changes / Keep editing. In EQ Library, Model → Manufacturer/search → root must unwind naturally; Back from root EQ Library and from Settings must return to My EQs; only Back from My EQs root exits. Check visible back arrows match system Back.
2. **Favorite stars in My EQs:** Open a managed headphone. Confirm every managed preset row has an outlined/filled star matching its Favorite state. Toggle one on and off without changing selected state, export status, or Flash state. Confirm a Favorite snapshot row uses the filled star to unfavorite while a personal import retains its remove action.
3. **Populated General EQs + batch Save:** Open EQ Library → General EQs. Confirm Bass Boost, Vocal Clarity, Treble Boost, Loudness, Podcast, Electronic, and Rock are present with sensible Sound/Genre/Utility classification and source attribution. Confirm the batch checkboxes start with none selected, Select all/Select none work, and Save selected saves the chosen General EQs and starts one active-output initial-export flow. Confirm no General preset is silently layered with a headphone EQ.
4. **Hide from EQ Library:** Hide at least one General EQ using Hide selected and one headphone EQ using its Hide action. Confirm both disappear from ordinary EQ Library browse/search. Hide an EQ that is already present in My EQs and confirm its My EQs selection, favorite state, current exported file/status, and Black Pearl Flash availability are not removed or reset.
5. **Settings → Hidden EQs / Unhide:** Confirm Settings shows the hidden count. Open Hidden EQs and confirm none are selected initially, Select all/Select none work, and Unhide selected restores only those EQs to normal library visibility. Confirm there is no Delete action. Fully close/reopen the app and confirm hidden state persists.
6. **Hide survives refresh:** Hide a canonical EQ, use Settings → Refresh now, and confirm it remains hidden after the refreshed catalog is promoted. Unrelated newly visible catalog entries must not inherit the hidden state. An already-saved My EQs copy remains untouched.
7. **New-EQ notification/review:** Add a never-managed headphone after explicitly choosing its EQs and confirm My EQs shows **Notify me about new EQs** ON by default. Toggle the switch OFF and ON and confirm the selected EQ set, export state, favorites, and Flash state do not change. If this exact candidate already contains a pending new-EQ review for a saved headphone, confirm the pending `new` / `updated` status is inline beside the selected/available counts and opens Review; new rows start with none selected; **Add selected** adds only checked rows; **Dismiss/Done** marks the batch reviewed without adding/hiding/deleting unchosen rows and the inline status clears immediately; Back leaves the batch pending. If a pending row belongs to a lineage you hide, confirm that hidden lineage no longer produces review attention while hidden. New-arrival cases that cannot be induced safely on-device are covered by the exact-head reconciliation/unit tests and are not a reason to manufacture catalog data on the phone.
8. **Compact personal import entry:** In My EQs, confirm the old large top Import PEQ button is gone. Confirm compact **+ Import** appears with **Saved snapshots & personal imports** and does not crowd the Black Pearl Connect/Connected control.
9. **Equalizer APO / AutoEq paste import:** Open + Import, explicitly paste a valid Equalizer APO / AutoEq PEQ, and confirm the authoritative preview shows the exact preamp, active-filter count, type, frequency, gain, and Q values. Save & export; confirm it appears in My EQs and the active-output initial export starts. Import must not flash Black Pearl.
10. **No-preamp + strict error handling:** Import a valid preset without a Preamp line and confirm the preview says **No preamp supplied** and the canonical value is not rewritten to 0 dB. Then make one Filter line malformed in an otherwise valid multi-filter preset and confirm Save is blocked with a visible line-level error rather than silently importing a partial EQ. Repeat with an unsupported active filter type and confirm Save remains blocked.
11. **Choose file is content-based:** Choose a file containing valid Equalizer APO / AutoEq text using a non-`.txt` filename/extension when practical and confirm it imports from its contents. Choose a file whose contents are not a supported importer and confirm a clear **This EQ format isn't supported yet** style error with no saved-state change. A UTF-8 BOM-bearing text file should still recognize its first Preamp/Filter line.
12. **Output/export regression smoke:** Import one freshly exported UAPP/ToneBoosters preset into UAPP. If Black Pearl is available, connect and flash one previously validated ordinary in-range preset to confirm the UI/data polish did not disturb the established Flash path. A repeat of the -11.9 dB hardware qualification is not required unless related Black Pearl/device/DSP code changed.

**Focused PASS:** all applicable twelve release-polish checks pass, with non-inducible catalog-arrival semantics green in automated tests; the final signed candidate may proceed to the public v0.3.0 release gate.

## STOP conditions

Stop testing and report the step if any of the following occurs:

- Android refuses to install the signed v0.3 APK over the installed v0.2.0 app or requires uninstalling first.
- Existing v0.2.0 selections, saved EQ state, or app-owned export records disappear unexpectedly after upgrade.
- The app crashes, repeatedly hangs, or cannot reopen after upgrade.
- Choosing an output hides otherwise valid curves from EQ Library.
- A new or newly reviewed EQ is silently selected merely because new-EQ notifications are ON.
- Toggling **Notify me about new EQs** changes the headphone's saved EQ selection, exported files/currentness, Favorite state, or Flash state.
- A hidden canonical lineage continues to create a persistent new-EQ review badge/prompt while hidden.
- Adding/saving selected EQs fails to initiate their expected initial export for the active output, or normal Export / Export all actions remain presented after the expected app-managed files are present and current.
- A document provider changes/normalizes the requested filename and EQ Library responds by deleting an otherwise successful newly created preset or leaves that preset permanently stuck in recovery.
- An unowned same-name file is overwritten/deleted, or a safe app-owned fallback file cannot be distinguished from it.
- A cleanup action deletes a file the app does not own.
- Black Pearl Flash changes playback gain by an amount other than the disclosed required adjustment, stacks a new EQ Library adjustment on top of the prior one, silently clamps an unrepresentable global gain request, or changes an unrelated non-EQ DAC setting.
- A Black Pearl band outside the currently validated ±10 dB filter-gain range is silently clamped/changed instead of being preserved with an explicit caution.
- Black Pearl Flash writes before the confirmation step.
- A profile labeled Exact is materially changed by its output conversion.
- The same acoustic tuning appears as duplicate catalog profiles when it should be one canonical tuning with provenance references.
- Historical revisions are silently replaced rather than remaining selectable.

If none occur, continue through the checklist.

## 1. Capture v0.2.0 state before upgrade

Before installing v0.3, open the currently installed v0.2.0 app and note at least one existing item that can be checked after upgrade:

- one saved headphone/profile selection, if present;
- one favorite/personal EQ, if present;
- one app-owned exported file, if present.

Do not clear app data and do not uninstall v0.2.0.

## 2. Install v0.3 in place

1. Install the latest signed `EQ-Library-v0.3.0-beta-<sha>.apk` over v0.2.0.
2. Confirm Android performs an update rather than installing a separate app.
3. Open EQ Library and confirm the primary navigation is **My EQs | EQ Library | Settings**.
4. Confirm existing v0.2.0 headphone selections are present under the UAPP/ToneBoosters output.
5. If a v0.2.0 favorite/personal EQ existed, confirm it also migrated to the UAPP/ToneBoosters My EQs collection rather than appearing automatically under every output.

**Pass:** v0.3 installs in place and existing user state is preserved under the UAPP output context.

## 3. Output selector must not filter the library

1. Open **Settings → Outputs** and enable at least UAPP/ToneBoosters and TRN Black Pearl. Optionally enable Universal PEQ, Poweramp, and Wavelet.
2. Return to **EQ Library** and search for a known headphone such as HIFIMAN Edition XS.
3. Note the available EQ profiles.
4. Switch the top output selector between UAPP/ToneBoosters and Black Pearl.
5. Confirm the same usable canonical profiles remain visible/selectable.
6. Confirm only their output status changes as appropriate: **Exact**, **Optimized**, or **Not exportable**.

**Pass:** output is operating context, never a catalog-visibility filter.

## 4. Browse, provenance, revisions, Unverified, and explicit new-EQ selection

1. Open a headphone with multiple sources/revisions, using Edition XS when practical.
2. Confirm a never-added headphone starts with **zero EQs selected**. There is no automatic-future-selection control in the library selection editor.
3. Explicitly select the profiles you want and add the headphone. In My EQs, confirm **Notify me about new EQs** is present and ON by default for the newly managed headphone.
4. Toggle that notification preference OFF and ON and confirm it never changes the saved selected-profile set by itself.
5. Confirm source/creator information and Source links are visible where available.
6. Confirm an older materially different revision can remain available through history rather than being overwritten by Latest.
7. If an Unverified community profile is available, confirm it is labeled **Unverified** / not independently verified and remains manually selectable.
8. Confirm enabling new-EQ notifications never silently selects an Unverified or Verified profile; selection occurs only through explicit checkbox/Add actions or Add selected in a review.

**Pass:** new selections start explicit/empty, notification is attention-only, and provenance, revision history, and trust state are distinct from output capability.

## 5. Output-specific My EQs and initial export

1. With UAPP/ToneBoosters active, open a never-added headphone, select at least one EQ, and tap **Add**.
2. Confirm Add saves exactly the selected EQs and initiates their initial export for the active output. If no export folder has been chosen yet and the active output needs file export, confirm the normal Android folder-selection flow is offered as part of that initial export.
3. After the expected files are present/current, confirm normal per-item **Export** and **Export all** recovery actions are not shown as routine next steps.
4. Save/favorite a second EQ or import a personal PEQ if practical.
5. Open **My EQs** and confirm the saved entries appear under **Headphones**.
6. Switch active output to Black Pearl.
7. Confirm UAPP-only selections do not automatically become Black Pearl selections.
8. Add at least one EQ while Black Pearl is active and confirm it appears in Black Pearl My EQs; where file export is applicable, confirm Add/Save initiates the active-output export rather than requiring a separate normal Export step.
9. Switch back to UAPP and confirm the UAPP collection is unchanged.
10. If General EQs are available, add one under **EQ Library → General EQs** and confirm it appears in the active output's **General EQs** section only.
11. Remove selected EQs from one managed headphone until none remain for the active output and confirm that headphone disappears from that output's My EQs collection without silently deleting retained files.

**Pass:** My EQs membership is independent per output, new headphones begin with explicit selections only, and Add/Save performs the initial export while preserving canonical source data.

## 6. General EQ browsing

1. Open **EQ Library → General EQs**.
2. Exercise **All**, **Sound**, **Genre**, and **Utility** filters where populated.
3. Confirm General EQs are standalone presets and are not silently layered onto a headphone EQ.
4. Confirm source/intent wording does not imply a genre preset is objectively correct merely because of its category.

**Pass:** General EQ classification and saving are understandable and independent from headphone correction.

## 7. UAPP/ToneBoosters export regression and recovery-only actions

1. Select **UAPP / ToneBoosters** as the active output.
2. Add/save an exportable headphone profile and let the initial Add/Save export complete.
3. Confirm its status is Exact/Optimized/Not exportable as appropriate.
4. Confirm the expected XML is created in the chosen SAF destination and imports successfully in UAPP/ToneBoosters.
5. Confirm preamp/headroom, filter count, frequencies, gains, Q values, and supported filter types correspond to the selected source.
6. For a source over 10 bands, confirm UAPP is labeled Optimized and only the first 10 source-priority bands are used.
7. Return to My EQs after a successful current export and confirm the per-item Export action is absent while the file is current.
8. If practical, delete that app-owned exported file outside the app, return/reopen My EQs, and confirm the recovery **Export** action becomes available again.
9. Use that recovery Export and confirm the missing app-managed file is recreated and the recovery action disappears again when current.

**Pass:** UAPP export is deterministic and source-preserving; Add/Save handles initial export, while explicit Export is a recovery action for missing/stale expected files.

## 8. Export all, provider-adjusted names, collision recovery, and ownership safety

1. Make at least two exportable EQs in the active My EQs collection need recovery export by removing or making their expected app-managed output files stale where practical.
2. Confirm **Export all** appears only because recovery work is pending and use it.
3. Confirm it writes/updates only the active output's pending app-managed presets.
4. After all exportable items are current, confirm Export all is no longer shown as normal pending work.
5. Place or retain an unrelated file in the destination with the same preferred human-readable filename as a preset if practical.
6. Export that preset and confirm EQ Library leaves the unrelated file untouched, creates a stable separately named app-owned file, tracks it, and clears the preset's recovery state after success.
7. If the selected Android document provider automatically changes or normalizes a requested display name/extension, confirm the newly created file is kept rather than deleted and My EQs immediately treats the tracked URI/content as current. Reopen the app and confirm it remains current.
8. When two app-managed presets have the same preferred human-readable name, confirm both export using distinct stable identity-derived filenames rather than leaving either in a permanent conflict/retry state.
9. Use a later Export/update for one of the provider-adjusted/fallback files and confirm the exact previously tracked app-owned URI is updated rather than creating an unnecessary duplicate merely because its actual name differs from today's preferred name.
10. Use an app cleanup/remove-with-files action for one EQ Library-owned item.
11. Confirm the exact owned file is removed while the unrelated same-name file and other external files remain untouched.

**Pass:** filename/provider differences never strand app-created output, collisions are resolved with stable app-owned files, currentness follows the tracked URI/content, and cleanup remains ownership-safe.

## 9. Black Pearl connection UX

1. Select **TRN Black Pearl** as the active output.
2. In Settings, enable **Direct Flash**.
3. Open **My EQs** with the DAC disconnected.
4. Confirm the top control shows a prominent red **Connect to DAC** state/action.
5. Confirm per-row **Flash** is visible but disabled while disconnected.
6. Connect the TRN Black Pearl to the Pixel 9 and use **Connect to DAC**.
7. Approve Android USB permission if requested.
8. Confirm My EQs reports the DAC as connected using the green connected state.

**Pass:** connection controls exist in My EQs only and do not interfere with file export/recovery behavior.

## 10. Black Pearl direct Flash — playback gain, non-cumulative behavior, and EQ safety

Use profiles whose required playback-gain adjustments are easy to distinguish. Prefer one with a known negative source preamp, a second with a different negative preamp, and a 0 dB profile when available.

1. Record the Black Pearl's current playback volume/global gain as the baseline and note any other DAC setting you can easily observe.
2. Tap **Flash** on the first profile.
3. Confirm a **Flash to Black Pearl?** confirmation appears before any write and explicitly discloses the required listening-volume/playback-gain change when nonzero.
4. Cancel once and confirm neither EQ nor playback gain changes.
5. Start Flash again and confirm.
6. Confirm the app reports **Flash successful**, the EQ is written to the DAC's currently active EQ slot, and the playback gain changes by the disclosed amount using the profile's required preamp/headroom.
7. Confirm unrelated DAC settings were not changed.
8. Flash a second profile with a different required negative playback-gain adjustment. Confirm the resulting attenuation replaces the first EQ Library-applied adjustment relative to the baseline; the two reductions must **not** accumulate.
9. Flash a profile requiring 0 dB playback-gain adjustment. Confirm the prior EQ Library-applied attenuation is removed so playback gain returns to the baseline that existed before EQ Library's adjustment, subject only to any independent user volume changes made between tests.
10. Audibly/visually confirm each flashed EQ is active where the Black Pearl exposes that state.

**Pass:** Direct Flash writes the current EQ slot and applies only the currently required EQ Library playback-gain adjustment, replacing rather than stacking prior EQ Library attenuation and leaving unrelated DAC settings untouched.

## 11. Black Pearl filter types, band limits, and validated-range caution

Use source profiles that exercise the available cases when practical.

1. Flash/export a profile containing Peak filters and confirm it succeeds when values are in the currently validated range.
2. Flash/export a profile containing a native Low Shelf and confirm the shelf remains a Low Shelf rather than being replaced with synthetic peaking filters.
3. Do the same for a High Shelf if a suitable profile is available.
4. For a source over 10 bands, confirm Black Pearl reports **Optimized**, warns that only the first 10 source-priority bands are used, and does not alter the canonical source record.
5. For a profile requiring nonzero source preamp or generated headroom, confirm it remains flashable when the required absolute playback gain is representable and that the confirmation discloses the required gain change.
6. Use the HIFIMAN Edition XS **Altruistic-Farmer275** profile (or another known equivalent test fixture) whose first 10 source-priority bands include the `13,500 Hz / -11.9 dB / Q 4.0` filter. Confirm Black Pearl **file export succeeds** and preserves `-11.9 dB` exactly rather than labeling the profile Not exportable or clamping it to `-10 dB`.
7. With the DAC connected, tap Flash for that profile. Confirm the dialog explicitly identifies the out-of-validated-range band/value, says the exact value will be sent unchanged/not clamped, includes any playback-gain and 10-band information that also applies, and offers **Cancel** / **Flash anyway**.
8. Tap **Cancel** first and confirm no EQ or global-gain write occurs.
9. Repeat, choose **Flash anyway**, and determine whether the physical Black Pearl accepts/applies the `-11.9 dB` band correctly. Confirm it is not silently clamped to `-10 dB`. Record the result because this is the evidence needed to widen the validated hardware range later.
10. If an out-of-range **absolute global playback gain** can be exercised safely and practically, confirm Flash fails clearly rather than silently clamping the requested global gain. Do not manufacture an unsafe listening condition merely to force this case; automated tests remain authoritative for the boundary condition.

**Pass:** native corroborated filter types are preserved, the 10-band limit is explicit, source band gains outside the currently validated ±10 dB range are preserved behind an explicit caution rather than silently changed, required playback gain is applied only when representable, and hard global-gain limits are never silently clamped.

## 12. Offline / last-known-good behavior

1. With a usable catalog already loaded, put the phone offline.
2. Relaunch EQ Library.
3. Search/open a previously available headphone and profile.
4. Confirm the saved catalog remains usable.
5. Trigger Refresh now if practical and confirm failure is non-destructive and the saved library remains available.
6. Restore network access.

**Pass:** a network outage never empties or blocks the last-known-good library.

## 13. Restart and basic accessibility check

1. Fully close and reopen EQ Library.
2. Confirm the active output and its My EQs collection persist correctly.
3. Confirm no unexpected duplicate/missing state appeared.
4. Increase Android font size and confirm the primary nav, output selector, My EQs actions, and Settings remain usable without clipped critical actions.
5. With TalkBack if practical, confirm Connect, recovery Export, Flash, Remove, output selector, and profile checkbox controls have understandable labels.

**Pass:** the candidate remains stable across restart and basic accessibility scaling.
