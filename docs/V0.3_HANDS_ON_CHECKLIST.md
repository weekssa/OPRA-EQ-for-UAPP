# EQ Library v0.3 Hands-On Validation

Use the latest **signed beta** artifact from `eq-library-community-v0.3`. Do not use the ordinary debug APK for the upgrade test.

This is the final device checkpoint before v0.3 can move toward `main` or public release.

## STOP conditions

Stop testing and report the step if any of the following occurs:

- Android refuses to install the signed v0.3 APK over the installed v0.2.0 app.
- The installer requires uninstalling v0.2.0 first.
- Existing v0.2.0 My Headphones selections, generated presets, saved app state, or app-owned export records disappear unexpectedly after upgrade.
- The app crashes, repeatedly hangs, or cannot reopen after upgrade.
- Selecting an EQ causes a device export without an explicit Export action.
- A cleanup action deletes a file the app does not own.
- A profile exported to UAPP or Black Pearl is structurally invalid or materially different from the profile shown in EQ Library without being labeled as converted/optimized.
- The same Edition XS tuning appears as duplicate catalog profiles when it should be one canonical profile with provenance references.
- Historical revisions are silently replaced rather than remaining selectable.

If none of those occur, continue through the full checklist.

## 1. Capture v0.2.0 state before upgrade

Before installing v0.3, open the currently installed v0.2.0 app and note at least one existing item that can be checked after upgrade:

- one My Headphones selection, if present
- one selected/generated preset, if present
- one app-owned exported file, if present

Do not clear app data and do not uninstall v0.2.0.

## 2. Install v0.3 in place

1. Install the latest signed `EQ-Library-v0.3.0-beta-<sha>.apk` over v0.2.0.
2. Confirm Android performs an update rather than asking to install a separate app.
3. Open EQ Library.
4. Confirm the app opens normally and still identifies as EQ Library.
5. Recheck the v0.2.0 state captured in step 1.

**Pass:** v0.3 installs in place and existing user state remains usable.

## 3. Browse, dedupe, provenance, and revision history

Use **HIFIMAN Edition XS** as the primary catalog validation sample.

1. Search for `Edition XS`.
2. Open the HIFIMAN Edition XS result.
3. Confirm the catalog does not show separate duplicate profiles for the same AutoEq/OPRA acoustic tuning.
4. Open the EQ/profile details.
5. Confirm source/provenance information is visible. The canonical data currently carries AutoEq as the primary measurement-derived source and OPRA as an additional mirror/reference for the matching tuning.
6. Confirm a Latest revision is identifiable.
7. Open revision history and confirm at least one older materially different revision remains selectable.
8. Switch between Latest and an older revision, then return to Latest.

**Pass:** one canonical tuning retains multiple provenance references and historical acoustic revisions instead of duplicating or overwriting them.

## 4. Selection must not export

1. Select an Edition XS EQ/revision.
2. Navigate around the app and return to the profile.
3. Confirm no device file was created merely because the EQ was selected.

**Pass:** selection and export remain separate actions.

## 5. Save / My EQs behavior

1. Save or favorite an Edition XS EQ if the surface offers that action.
2. Open My EQs.
3. Confirm the saved item is present and can be reopened.
4. If personal/imported EQ support is surfaced in this build, open the entry point and confirm it is clearly distinct from published source profiles.

**Pass:** saved/personal library state is understandable and does not alter the published catalog item.

## 6. UAPP export regression

1. Return to the Edition XS Latest revision.
2. Choose **UAPP / ToneBoosters** as the target device.
3. Review the compatibility/conversion result before exporting.
4. Export explicitly.
5. Confirm the app reports success and the expected XML file is created in the chosen UAPP destination.
6. Import/open the preset in UAPP.
7. Confirm preamp, filter count, frequencies, gains, Q values, and filter types are sensible and correspond to the selected EQ.
8. Return to EQ Library and confirm the source profile itself has not been rewritten by the export representation.

**Pass:** UAPP export remains valid and explicit, with the normalized source tuning preserved separately.

## 7. TRN Black Pearl export regression

1. Use the same Edition XS revision.
2. Choose **TRN Black Pearl**.
3. Review whether the result is Exact, Converted, Optimized, or Not faithfully representable.
4. Export explicitly.
5. Confirm the generated Black Pearl preset respects the device's 10-band PK constraints.
6. Load or inspect the preset on the Black Pearl path available to you.
7. Confirm the app does not claim an exact representation when conversion/optimization was required.

**Pass:** Black Pearl conversion is bounded to device constraints and the compatibility label is truthful.

## 8. Export ownership and cleanup safety

1. Identify one file created by EQ Library during this test.
2. Place or retain an unrelated file in the same general destination if practical.
3. Use the app's targeted cleanup/delete action for the EQ Library-owned item.
4. Confirm the app-owned file is removed as expected.
5. Confirm the unrelated file remains untouched.
6. If a full saved-library cleanup action is available, review its scope before confirming and verify it does not remove external files the app does not own.

**Pass:** cleanup is scoped to app-owned records/files and does not behave like a broad folder delete.

## 9. Offline / last-known-good behavior

1. With a usable catalog already loaded, put the phone offline or disable network access for the test.
2. Relaunch EQ Library.
3. Search for Edition XS again.
4. Open the previously available profile/revision.
5. Confirm the last-known-good catalog remains usable.
6. Restore network access.

**Pass:** a source/network outage does not invalidate the last usable catalog.

## 10. Final reopen check

1. Fully close EQ Library.
2. Reopen it.
3. Confirm the app starts normally.
4. Recheck the saved/favorite item and My Headphones state used earlier.
5. Confirm no unexpected duplicate or missing state appeared after restart.

**Pass:** upgraded state remains stable across a full app restart.

## Known deferred hardware validation

These do **not** block the software checkpoint unless their behavior regresses outside the already documented hardware-validation limitation:

- TOPPING DX5 II hardware import/application validation
- TOPPING DX1 II hardware import/application validation

The v0.2 device-target abstraction and target isolation still need to remain intact; only physical Topping hardware confirmation is deferred.

Record one of:
