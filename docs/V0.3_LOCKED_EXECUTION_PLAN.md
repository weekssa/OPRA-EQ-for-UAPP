# EQ Library v0.3 Locked Execution Plan

This document records the currently approved product direction and execution order for the v0.3 multi-source EQ Library milestone. It supplements `docs/CHATGPT_PROJECT_RUNBOOK.md`, `docs/ARCHITECTURE.md`, `docs/PHASE1_DECISIONS.md`, `docs/SOURCE_INGESTION_STRATEGY.md`, and `docs/AUTONOMOUS_V0.3_PLAN.md`.

Historical execution note: the `eq-library-community-v0.3` / PR #3 implementation completed its signed Pixel 9 / TRN Black Pearl hands-on gate and was merged to `main`. Final v0.3.0 release-polish work now runs on `v0.3-release-polish` / PR #4 and is controlled by `docs/V0.3_RELEASE_POLISH_PLAN.md`; that later plan supersedes this document where the final scope differs.

Later explicit product approvals recorded in `docs/PHASE1_DECISIONS.md` supersede earlier rules in this plan when they conflict. In particular, the 2026-08-31 approvals changed new-headphone defaults to zero selected/auto-include OFF, made Add perform the initial export with recovery-only Export UI, and approved required Black Pearl global-gain adjustment during confirmed direct Flash.

## 1. Product identity and navigation

The product name is **EQ Library**. OPRA is one catalog source, not the product identity.

The Android application ID remains `com.weekssa.opraeqforuapp`; renaming the user-facing product must not rotate the application ID or signing identity.

Approved primary navigation:

- **My EQs**
- **EQ Library**
- **Settings**

The current output/device context is visible in the top app bar on the primary content screens, for example:

`EQ Library                              Black Pearl ▾`

and

`My EQs                                  Black Pearl ▾`

The active output/device is an operating context, **not a catalog visibility filter**. Selecting Black Pearl, UAPP, Poweramp, Wavelet, or another output must never hide otherwise valid canonical EQ curves from EQ Library.

Final release-polish Back behavior uses My EQs as the start destination: nested EQ Library/My EQs states unwind first, root EQ Library and Settings return to My EQs, and only Back at My EQs root exits. Managed My EQs preset rows also expose the Favorite star so users do not need to return to EQ Library merely to favorite/unfavorite a saved profile.

## 2. Initial output/device contexts

Initial selector/settings choices:

1. USB Audio Player PRO / ToneBoosters
2. TRN Black Pearl
3. Universal Parametric EQ
4. Poweramp / Poweramp Equalizer
5. Wavelet

Additional outputs may be added after format/device behavior is validated. Hardware-validation-pending targets remain clearly marked internally until proven.

For each active output, every canonical EQ is independently evaluated as:

- **Exact / preserved**
- **Optimized**
- **Not exportable / not faithfully representable**

Those states inform the user but do not remove the EQ from the library.

## 3. EQ Library browsing and selection defaults

EQ Library uses two primary sections:

- **Headphones**
- **General EQs**

General EQs use user-facing filters:

- **All**
- **Sound**
- **Genre**
- **Utility**

Examples of Sound include Bass Boost, Sub-bass Boost, Warm, Bright, Treble Reduction, and Vocal Presence. Genre remains source-authored/traceable only. Utility includes cases such as Loudness/Low-volume and Speech/Podcast.

No General EQ is automatically layered on top of a headphone EQ in v0.3. General EQs are standalone presets until a separately approved layering design exists.

For a headphone never saved for the active output, start with **no EQs selected** and **Automatically include new EQs OFF**. The user deliberately chooses what to add. Existing selections are preserved across upgrades. Select all/none remain explicit actions.

## 4. My EQs, Add, and export recovery

My EQs is output/device-specific. A user's Black Pearl collection and UAPP collection may differ without deleting or mutating canonical library data.

My EQs is grouped into:

- **Headphones**
- **General EQs**

The normal flow is `choose EQs -> Add -> saved + initial export`. Add saves the current-output membership and immediately exports each selected exportable preset. If an export folder is required and no retained folder exists, Add requests it through Android's system picker and completes export after access is granted. Add never directly flashes hardware.

Export UI is recovery-only. If every expected app-owned file is present/current, no Export or Export all control and no routine export-status message is shown. If files are missing/stale, generated output changed, or access needs repair, show a concise affected count and only the relevant per-row Export / Export all recovery actions. A not-exportable profile remains saved without falsely creating an export-recovery item.

Remove remains explicit. Removing the last selected EQ for a headphone removes that headphone row entirely from My EQs for the active output, while other outputs remain untouched.

## 5. TRN Black Pearl UX and behavior

Black Pearl connection/flash controls exist only in **My EQs** and its headphone-detail management surfaces.

When Black Pearl is the active output:

- disconnected: show a prominent red **Connect to DAC** action/status;
- connected: show a green connected status;
- Flash remains visible but disabled while disconnected or when the profile cannot fit Black Pearl's validated filter/band/range limits;
- file Export is independent of USB connection and is normally completed during Add;
- Flash is independent of file Export;
- Flash requires confirmation before writing;
- after success, show a transient **Flash successful** state and then return the control to Flash;
- direct Flash is opt-in in Settings and defaults OFF;
- EQ Library does not expose DAC reconstruction filter, gain mode, amp topology, balance, microphone settings, or other unrelated Black Pearl controls.

### Black Pearl reference implementations

Behavior/protocol references include:

- `https://github.com/cheesyserg/pyBlackPearl`
- `https://github.com/cheesyserg/BlackPearlControl-Android`
- `https://github.com/DisYaBoiRalph/BlackPearlControl`

These references are GPL-licensed. EQ Library is Apache-2.0. Use them only to understand observable protocol/device behavior and independently implement the EQ integration. Do not copy GPL implementation code into EQ Library.

Known protocol evidence independently implemented/validated in the project includes USB VID `0x3302`, PID `0x43E8`, HID report `0x4B`, global playback gain command `0x03`, PEQ command `0x09`, flash/save command `0x01`, ten hardware PEQ bands, an active-slot value used when writing PEQ data, and native Peak/Low Shelf/High Shelf type codes.

### Black Pearl preamp/headroom behavior — approved 2026-08-31

The Black Pearl exposes global playback gain and the user explicitly approved using it when Flash needs source preamp or generated safety headroom for faithful playback.

Required implementation:

1. Read the current Black Pearl global gain and active EQ slot before Flash.
2. Determine the required effective playback attenuation from source preamp or separately generated EQ Library safety headroom.
3. Replace any prior EQ Library-applied attenuation rather than accumulating reductions across flashes.
4. Write the new global gain using the device's actual raw/dB mapping, not the reference app's approximate percentage import mapping.
5. Refuse rather than silently clamp when the required result is outside the validated hardware range.
6. Write all ten hardware PEQ bands (padding unused bands flat), latch, and persist.
7. Confirmation discloses the exact gain adjustment that will be made.
8. A later 0 dB requirement removes a prior EQ Library-applied attenuation when tracked/read-back state establishes it safely.
9. Do not change DAC reconstruction filter, gain mode, amplifier topology, balance, microphone controls, or other unrelated settings.

## 6. Catalog refresh behavior

The app remains offline-first and opens immediately from last-known-good local catalog state.

Foreground refresh rule:

- on app launch/resume, inspect the timestamp of the **last successful** catalog refresh;
- if the last successful refresh is less than approximately 24 hours old, use cache and do not perform a normal due refresh;
- if approximately 24 hours or older, show cached data immediately and refresh opportunistically in the background;
- a failed attempt does not reset the 24-hour success clock;
- no internet must never empty or block the app;
- on failure, keep the cached library and show concise status such as **Couldn't refresh EQ Library — using your saved library**;
- keep approximately-daily WorkManager checks as a backup path;
- retain manual **Refresh now** in Settings.

## 8. Configuration/variant rule for community EQ discovery

Do not block a usable community EQ merely because every physical configuration detail is not stated.

Default rule:

- if the source explicitly names a materially relevant configuration such as nozzle, pad, revision, ANC mode, or other acoustic mode, preserve that configuration as a distinct labeled headphone/profile identity;
- for SIMGOT EW300, an explicitly stated nozzle belongs in the user-visible identity/profile grouping for that nozzle;
- if no such configuration is stated, place the EQ in the generic/base model bucket, for example generic **EW300**;
- never infer an unstated nozzle/pad/mode from unrelated context;
- later evidence may refine an identity, but must not silently rewrite a genuinely stated variant.

This rule applies to all priority models and future community discovery.

## 9. Public community source policy

The primary growth mechanism is source discovery from public headphone/audio communities, **not user push submissions**.

Priority community surfaces:

- Reddit audio communities
- Head-Fi
- Audio Science Review
- The HEADPHONE Community / Headphones.com
- additional public communities qualified over time

The project owner has stated that publicly posted EQ coefficient data from the headphone communities they use is approved for this project. Treat ownership/redistribution review of ordinary public numeric EQ coefficients from those communities as non-blocking for this project unless a source presents a specific contrary restriction.

Still required:

- preserve creator/username and original permalink/source;
- preserve exact source-authored coefficients;
- do not copy unrelated forum prose;
- do not access private/restricted/authenticated content or bypass controls;
- do not invent authorship, target, or acoustic configuration;
- ambiguous duplicate/revision/identity cases may remain quarantined without blocking the rest of the catalog.

The GitHub `Submit an EQ source` Issue Form may remain as a small optional contribution route, but it is not the primary population strategy and must not become an end-user requirement.

## 10. Discovery architecture and coverage ledger

Build recurring discovery around the same deterministic publication pipeline used by focused/manual discovery:

`discover -> retrieve original source -> parse exact coefficients -> classify headphone/general identity -> provenance -> dedupe/revision -> publish Unverified/Verified or quarantine`

High-signal discovery patterns include structured PEQ markers such as:

- `Preamp:`
- `Filter 1:`
- `ON PK`
- `Fc`
- `Gain`
- `Q`
- `parametric EQ`
- `PEQ`
- known structured preset attachment/file formats

Create and maintain machine-readable coverage state per source/headphone where practical, including:

- source searched
- last search attempt
- last successful search
- query/cursor/high-water mark
- candidates found
- candidates published
- duplicates
- held/rejected candidates with reason

A zero-result search must be distinguishable from a headphone/source that has never been searched.

Focused priority-headphone searches and broad scheduled discovery must feed the **same** canonical ingestion/dedupe/revision tooling so focused work is not throwaway data.

## 11. General EQ source expansion

General EQ population should also come primarily from public qualified sources and creator/community discovery, not a push-submission dependency.

Only classify a preset as Sound/Genre/Utility when the source itself provides enough intent/context to support that classification. Preserve exact coefficients and source terminology. Do not invent a genre claim from filter shape alone.

Final release-polish implementation uses the MIT-licensed ParaEQ built-ins as the first populated General EQ source. The qualified seed contains Bass Boost, Vocal Clarity, Treble Boost, Loudness, Podcast, Electronic, and Rock; Electronic/Rock are Genre because the source explicitly names them as such.

The existing generic General preset ingestion tooling remains the lower-level canonical path. Structured headphone-only Issue Form semantics must not be misused to create fake headphone identities for General EQs.

## 12. Execution order from this checkpoint

Proceed without routine user updates. Stop only for a genuine blocker or hands-on testing.

### A. Documentation lock

- Keep current approved product refinements synchronized across the mandatory runbook/architecture/decision chain.

### B. Priority library expansion

- Build/extend discovery inputs for the eight priority models across qualified sources.
- Add coverage-ledger state.
- Preserve explicit configuration metadata; generic bucket when configuration is unstated.
- Validate dedupe, revisions, arbitrary band counts, missing source preamp, Unverified promotion, and canonical identity.

### C. Recurring community discovery

- Move Reddit, Head-Fi, ASR, and HEADPHONE Community from primarily curated inputs toward recurring targeted discovery with cursors/high-water marks.
- Keep ordinary failures isolated and preserve last-known-good catalog.
- Add new public communities only through a documented source qualification entry.

### D. Global output-context Android refactor

- Maintain persisted active output/device context plus enabled selector options.
- Do not hide canonical library curves because of active output.
- Show Exact/Optimized/Not exportable information instead.
- Keep My EQs output-specific.

### E. Add/export flow

- Default new headphone selection to zero profiles and auto-include OFF.
- Add saves membership and performs initial export.
- Hide Export UI while files are current; surface concise recovery controls/count only when currentness checks find missing/stale output or access repair is needed.
- Remove empty headphone records after the last EQ is removed.

### F. General EQ Android UX

- Keep approved **Headphones | General EQs** EQ Library sections and **All | Sound | Genre | Utility** filters.
- Keep General presets standalone in v0.3.

### G. Foreground/currentness refresh

- Keep last-success-based ~24-hour opportunistic refresh on launch/resume.
- Keep cache usable and errors non-blocking.
- Retain WorkManager backup and manual Refresh now.

### H. Black Pearl direct Flash

- Extend the independent EQ USB/HID implementation with exact global-gain read/write required for approved preamp/headroom application.
- Keep direct Flash behind Settings opt-in.
- Preserve connection status, confirmation, active-slot write, persistence, and success/failure feedback.
- Do not implement unrelated DAC controls.

### I. Signed test candidate

Do not ask the user to test until applicable automated gates pass and a signed v0.3 upgrade APK is ready with one consolidated checklist.
