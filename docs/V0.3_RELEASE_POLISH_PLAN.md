## 2. Living canonical archive — locked PR #4 behavior

EQ Library is a living archive, not a disposable mirror of currently reachable source pages.

The project owner has verified that the sources being archived have explicit permission for the structured EQ data and that none of the approved sources are link-only. Therefore:

- once a genuine canonical EQ has been validly published, it remains in the current archive indefinitely;
- once a genuine acoustic revision has been validly published, that revision remains in the current archive indefinitely;
- source movement, URL loss, deletion, pausing, or retirement changes provenance/status only and must not remove archived acoustic data;
- formatting or application-modeling repairs must not manufacture fake acoustic revisions, but must not erase genuine archived history;
- identity normalization/alias improvements may change routing/presentation only when the archived acoustic lineage is preserved;
- Git history alone is not sufficient protection: previously published genuine canonical EQs/revisions remain represented in the **current published catalog**.

Catalog publication/currentness validation must reject a candidate that loses a previously published genuine canonical profile/revision or mutates an archived acoustic revision in place.

This archive rule is separate from local My EQs membership. A user may remove an EQ from an output-specific My EQs collection or remove app-owned exported files through an explicit local action; that never deletes the public canonical archived EQ.

## 3. Hide / Unhide — reversible local visibility only

Hide is local presentation state, never an archive mutation.

- Hidden state is global across outputs and is stored locally in Preferences DataStore as stable canonical profile IDs.
- Do not remove hidden EQs from the canonical catalog, validated cache, revision history, Room saved/My EQs state, or exported-file ownership state.
- Hidden state survives restart and catalog refresh.
- A hidden lineage stays hidden across genuine future revisions; unrelated new lineages remain visible by default.
- Hidden EQs are omitted from ordinary EQ Library browse/search.
- Hiding an already-saved EQ must not change its My EQs selection, export/currentness, files, Favorite membership, or Black Pearl Flash state.
- General EQ batch selection starts with none selected and provides Select all, Select none, Save selected, and Hide selected.
- Settings exposes **Hidden EQs** with count, none selected by default, Select all, Select none, and Unhide selected. There is no Delete action.

## 4. New-EQ notification/review — final locked v0.3 behavior

The old automatic-future-selection model is superseded for the final v0.3 release.

### Selection defaults

- A never-added headphone starts with **zero EQs selected**.
- The user explicitly selects the EQs they want before Add/Save.
- Verified and Unverified usable canonical PEQs remain manually selectable.
- Select all / Select none are explicit selection actions.
- Output capability is never a catalog/selection filter.
- No current or future EQ is silently selected because it is verified, newly published, or covered by a notification preference.

### Per-headphone notification preference

After a headphone is saved in My EQs it exposes **Notify me about new EQs**.

- The notification preference starts **ON** for newly managed headphones.
- It is an attention/review preference only; it never changes saved selection by itself.
- The legacy storage/domain field name `autoIncludeNewProfiles` may remain through the v0.3 migration boundary, but its final v0.3 meaning is notification-only.

When notification is ON:

- a newly published verified or unverified usable EQ for that headphone may create a pending review;
- a materially changed selected tuning may also create a pending review;
- new EQ rows in the review start with **none selected**;
- **Add selected** adds exactly the checked new EQs to the active output's saved selection and starts their normal initial export where representable;
- **Dismiss** marks the current batch reviewed without selecting, hiding, deleting, or exporting unchosen EQs;
- Android/visible **Back** leaves the review pending.

When notification is OFF:

- future EQs still appear normally in EQ Library;
- they do not create a per-headphone new-EQ review prompt;
- turning notification off clears the current pending attention state without changing the saved EQ selection.

### Hide interaction

A hidden canonical lineage must not create a My EQs new-EQ badge/review prompt while hidden, including later genuine revisions of that lineage. Suppressing the prompt is presentation-only: hiding an already-selected EQ still preserves its My EQs selection, export/currentness, files, Favorite state, and Flash state.

## 5. Personal PEQ import — compact canonical ingestion

The large top-area Import PEQ control is replaced by compact **+ Import** beside **Saved snapshots & personal imports**.

The dedicated import surface provides:

- explicit clipboard Paste; clipboard is never read automatically;
- Android system Choose file;
- required Manufacturer, Headphone model, and EQ name;
- optional Target/note;
- user-facing initial format label **Equalizer APO / AutoEq text**;
- an authoritative parsed preview before Save.

Input architecture is:

`paste/file -> format parser -> canonical PEQ -> validation -> active-output conversion/export`

For v0.3:

- contents, not filename extension, select the supported importer;
- supported Peak/PK/PEQ, Low Shelf/LS/LSC, and High Shelf/HS/HSC active filters preserve exact parsed frequency/gain/Q;
- source Preamp is optional and remains null when omitted;
- blank/comment lines and explicitly OFF filters may be ignored;
- malformed filter-looking lines or unsupported active filter types block Save with a visible error;
- no Save is allowed while a blocking parse/validation issue remains;
- never silently clamp, truncate, invent, substitute, or import only a valid subset;
- canonical ingestion retains the full supported filter count; target band limits apply only at output conversion;
- **Save & export** saves the personal EQ and begins the active-output initial export when representable;
- import never automatically flashes hardware;
- manual filter-by-filter editing and additional XML/JSON/CSV/Peace import adapters remain outside v0.3.

## 6. Architecture boundaries

PR #4 preserves the existing separation of concerns:

- source/input adapters normalize supported external data into device-independent canonical PEQ;
- canonical validation is separate from output capability;
- output converters apply only documented target-specific limits/optimizations;
- living archive policy is publication behavior;
- Hide/Unhide is local presentation state and never mutates canonical data;
- My EQs membership is output-specific and independent from global hidden-library visibility;
- new-EQ notification is local attention state and never performs implicit selection;
- file import uses Android's document picker without broad storage permission.

## 9. Implementation checkpoint

The approved archive-preservation, Hide/Unhide, General batch Save/Hide, personal-import redesign, explicit notification-only new-EQ review implementation, source-agnostic information-hierarchy cleanup, and compact managed-headphone action row are present on `v0.3-release-polish`.

The final new-EQ implementation deliberately keeps the legacy persisted boolean field name through v0.3 while changing its semantic use to notification/review only. Reconciliation never auto-selects a newly discovered EQ. Hidden canonical lineages have their review-attention flags suppressed only in the UI projection so underlying selection/source/export state is unchanged.

The managed-headphone density polish is presentation-only around actions/status: it shortens **Connect to DAC** to **Connect** on the detail page, shortens **Manage preset selection** to **Manage presets**, preserves connection/disabled/error behavior, keeps at least a 48 dp minimum action height, and moves pending review attention into the selected/available summary line. The review-state fix observes managed profile flags directly so completing a review updates that inline status immediately. It does not change Black Pearl protocol/DSP behavior or preset-selection semantics.

Black Pearl protocol/DSP code was not changed by this release-polish work, so the established full Black Pearl hardware qualification remains valid; only the focused ordinary Flash smoke is required unless a later diff touches device/DSP behavior.

Any previously signed PR #4 APK is superseded once the source head changes. The final hands-on APK must be built and signed from the final synchronized exact head.
