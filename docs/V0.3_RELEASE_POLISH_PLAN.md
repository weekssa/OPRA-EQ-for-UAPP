## 2. Living canonical archive — locked PR #4 behavior

EQ Library is a living archive, not a disposable mirror of currently reachable source pages.

The project owner has verified that the sources being archived have explicit permission for the structured EQ data and that none of the approved sources are link-only. Therefore:

- once a genuine canonical EQ has been validly published, the canonical EQ remains in the current archive indefinitely;
- once a genuine acoustic revision has been validly published, that revision remains in the current archive indefinitely;
- a source moving, changing URL, going offline, being deleted, pausing publication, or being retired must not remove the archived EQ or any genuine revision;
- provenance may be updated to a new confirmed URL, and source availability/lifecycle metadata may change, but the archived acoustic record remains;
- source unavailability is status/provenance metadata, not a deletion instruction;
- formatting-only or application-modeling corrections must not manufacture fake acoustic revisions, but they also must not erase genuine archived acoustic history;
- identity normalization/alias improvements may change presentation or canonical routing, but must preserve the archived EQ/revision lineage rather than dropping the acoustic record;
- Git history is not sufficient protection by itself: previously published genuine canonical EQs/revisions must remain represented in the **current published catalog**.

Catalog publication/currentness validation must enforce this invariant. A candidate publication that loses a previously published canonical EQ or genuine revision must fail rather than silently publishing the loss. The implementation may remap an identity only when the same archived acoustic record is preserved under the documented canonical lineage.

This archive rule is distinct from local My EQs membership. A user may remove an EQ from an output-specific My EQs collection or delete an app-owned exported file through an explicit local action; that must never delete the canonical archived EQ from the public catalog.

## 3. Hide / Unhide — reversible local visibility only

Hide is a local presentation preference, never an archive mutation.

### Storage and identity

- Hidden state is global across output contexts because it describes library visibility, not export membership.
- Store hidden canonical profile identities locally in Preferences DataStore as a set of stable canonical profile IDs.
- Do not remove hidden EQs from `catalog/catalog.json`, the validated local catalog cache, revision history, Room saved/My EQs state, or exported-file ownership state.
- Hidden state survives app restart and catalog refresh.
- A hidden canonical EQ remains hidden when a new genuine revision of that same canonical profile is published.
- A newly published unrelated canonical EQ is visible by default.

### Normal library behavior

- Hidden EQs are omitted from normal EQ Library browse/search/review lists.
- Hiding an EQ that is already selected/saved in My EQs must **not** remove it from My EQs, alter its active-output selection, invalidate current export state, delete files, unfavorite it, or change Black Pearl Flash state.
- Hide must be reversible without re-downloading or reconstructing the EQ.
- Hide applies to canonical headphone EQs and General EQs; it is not a General-only mechanism.

### General EQ review behavior

For the General EQ review/list selection surface:

- batch-action checkboxes start with **none selected**;
- provide **Select all** and **Select none**;
- provide **Save selected** for normal Add/Save behavior;
- provide **Hide selected** for local visibility curation;
- Hide selected does not save, export, or delete those EQs;
- after a successful hide action, a concise reversible confirmation/Undo may be shown where practical.

### Settings → Hidden EQs

Settings exposes **Hidden EQs** with the current hidden count. Opening it shows the hidden archive entries using the familiar batch-checkbox pattern:

- no rows selected initially;
- **Select all**;
- **Select none**;
- **Unhide selected**;
- enough context to identify each EQ: headphone/model when applicable, display/tuning name, creator/source/category where available;
- no Delete action.

Unhide removes only the local hidden marker and returns the EQ to normal library visibility.

## 4. Personal PEQ import — compact entry point and canonical ingestion

The current large `+ Import PEQ` button below the Black Pearl connection control consumes too much My EQs space and visually competes with the DAC action. PR #4 replaces that presentation.

### My EQs entry point

- Remove the large top-area Import PEQ button.
- Show a compact **+ Import** action alongside the **Saved snapshots & personal imports** section heading.
- Import remains a secondary library action; the Black Pearl Connect/Connected control remains the primary hardware action when Black Pearl is active.

### Import surface

Tapping **+ Import** opens a dedicated Import personal EQ screen/sheet rather than squeezing the workflow into the current multi-field AlertDialog.

The import surface provides:

- **Paste PEQ text** / explicit clipboard-paste action;
- **Choose file** through Android's system document picker;
- required Manufacturer;
- required Headphone model;
- required EQ name;
- optional Target / note;
- a user-facing format label of **Equalizer APO / AutoEq text** for the initially supported syntax;
- a parsed preview before Save.

Do not read the clipboard automatically. Clipboard access occurs only after the user explicitly taps the paste action.

### File extension versus content

The file extension does **not** select the conversion path. Contents do.

The ingestion architecture is:

`paste/file -> format parser -> canonical PEQ -> validation -> active-output conversion/export`

For v0.3:

- recognize the de-facto Equalizer APO / AutoEq parametric text syntax regardless of the selected filename extension;
- a `.txt` extension is not required if the contents are valid supported PEQ text;
- selecting an arbitrary file does not imply arbitrary-format support;
- if the contents do not match a supported importer, show a clear **This EQ format isn't supported yet** style error and leave saved state unchanged;
- future XML/JSON/CSV/Peace/device-specific importers are separate input adapters that must normalize into the same canonical model before output conversion.

### Equalizer APO / AutoEq text syntax

The initially supported text form includes the common structure:

```text
Preamp: -6.4 dB
Filter 1: ON PK Fc 31.5 Hz Gain 2.1 dB Q 0.70
Filter 2: ON LS Fc 105 Hz Gain 1.8 dB Q 0.71
Filter 3: ON HS Fc 8000 Hz Gain -1.2 dB Q 0.80
```

Recognized source aliases may include the parser's existing Peak/PK/PEQ, Low Shelf/LS/LSC, and High Shelf/HS/HSC spellings. Preamp is optional and remains null when omitted. Canonical ingestion preserves the full supported active filter count; device band limits are applied only at the output conversion boundary.

### Strict user-facing validation

The current low-level parser is intentionally tolerant for source ingestion and can ignore unknown lines. The personal-import UX must add a stricter validation layer so a user cannot unknowingly import a partial EQ.

Required behavior:

- blank lines and comments may be ignored;
- disabled `OFF` filters may be ignored as explicitly disabled input;
- a line that looks like a filter but is malformed must produce a visible validation error rather than silently disappearing;
- an unsupported active filter type must produce a visible validation error rather than being silently dropped;
- supported active Peak/Low Shelf/High Shelf filters must retain their exact parsed frequency/gain/Q values;
- every imported supported filter that requires Q must have a valid Q;
- no Save is allowed when the visible parse contains an unresolved error;
- never silently clamp, truncate, invent, or substitute filters during import.

### Parsed preview

Before Save, show the exact canonical interpretation, including:

- preamp value, or **No preamp supplied**;
- active filter count;
- numbered filter rows with type, frequency, gain, and Q;
- any blocking validation problem in context.

The preview is authoritative: the EQ shown there is the EQ that will be saved canonically.

### Save and export

- The completion action is **Save & export** when the active output has an exportable representation.
- Saving creates the personal EQ in the active output's My EQs collection and initiates the same initial-export flow used by other Add/Save operations.
- If SAF folder authorization is needed, request it through the existing system picker and complete export afterward.
- If the active output cannot export the canonical EQ, preserve the personal EQ locally and report that output limitation rather than mutating the canonical source.
- Import never automatically flashes hardware; Black Pearl Flash remains a separate explicit confirmed action.
- Manual filter-by-filter EQ editing is out of scope for v0.3.

## 5. Architecture boundaries

PR #4 must preserve the existing separation of concerns:

- input-format adapters parse supported external representations;
- the canonical PEQ model is device-independent;
- canonical validation is independent from active-output capability;
- output converters consume canonical data and apply only documented target-specific limits/optimizations;
- Hide/Unhide is local presentation state and never mutates canonical catalog data;
- My EQs output membership remains separate from global hidden-library visibility;
- file import uses the Android document picker without broad storage permission.

## 6. Automated regression requirements

Do not weaken existing validation. Add focused coverage for at least:

1. **Archive preservation:** a candidate publication cannot remove a previously published canonical profile.
2. **Revision preservation:** a candidate publication cannot remove a previously published genuine revision.
3. **Source disappearance:** changing source lifecycle/availability or URL does not remove archived acoustic data.
4. **Identity migration:** safe canonical alias/remap preserves the archived acoustic record rather than dropping it.
5. **Hide persistence:** hidden canonical IDs survive DataStore restart/reload and catalog refresh.
6. **Hide scope:** hidden EQs disappear from normal browse/search but an already-saved My EQs item remains saved/current.
7. **Future revision behavior:** a new revision of a hidden canonical profile remains hidden; unrelated new profiles do not become hidden.
8. **Unhide:** Settings batch Unhide restores normal visibility without changing My EQs/export state.
9. **Import exactness:** supported Equalizer APO / AutoEq text preserves preamp/null-preamp, filter count, type, frequency, gain, and Q.
10. **Strict import errors:** malformed filter-looking lines and unsupported active filter types block Save instead of producing a partial EQ.
11. **Extension independence:** valid supported PEQ text imports even when the filename does not end in `.txt`; unsupported contents fail clearly regardless of extension.
12. **Personal initial export:** successful Save & export initiates active-output initial export and leaves recovery-only Export hidden once current.
13. **No hardware side effect:** personal import never performs a Black Pearl USB write.

## 7. Focused Pixel 9 hands-on addendum

The final signed PR #4 candidate must pass all of the existing release-polish checks plus the following additions:

1. **Hide from General EQ review:** verify none selected by default, Select all/none, Hide selected, and that hidden entries disappear from normal General EQ browsing without being deleted.
2. **Hidden EQ settings:** verify Settings shows the correct hidden count, Hidden EQs opens with none selected, Select all/none works, Unhide selected restores normal visibility, and state survives full app restart.
3. **Refresh persistence:** hide at least one canonical EQ, Refresh the catalog, and verify it remains hidden while an existing My EQs copy remains untouched.
4. **Compact import entry:** verify the large top Import PEQ button is gone and **+ Import** appears with Saved snapshots & personal imports without crowding the Black Pearl connection control.
5. **Paste import:** paste a valid Equalizer APO / AutoEq PEQ, confirm the parsed preview exactly matches preamp/filter values, then Save & export and verify the item appears in My EQs and exports for the active output.
6. **No-preamp import:** import a valid preset without Preamp and confirm the preview states No preamp supplied and the canonical source is not rewritten to 0 dB.
7. **Malformed import:** make one filter line malformed in an otherwise valid preset and confirm Save is blocked with a visible error; no silent 9-of-10 style partial import is allowed.
8. **File-content import:** choose a file containing valid supported PEQ text and verify contents are recognized independent of extension; choose unsupported contents and verify a clear unsupported-format error with no saved-state change.
9. **Regression smoke:** complete the existing Back/Favorite/General Add/UAPP import smoke checks and, when Black Pearl is available, one ordinary previously validated in-range Flash. Full Black Pearl protocol requalification is unnecessary unless device/DSP code changes.
