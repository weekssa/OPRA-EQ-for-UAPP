# EQ Library v0.3 — Whole-app UX density and hierarchy audit

Status: **design audit only — implementation pending explicit approval of this consolidated pass**.

This audit follows the approved source-agnostic information-hierarchy cleanup and the later user request to apply the same task-first thinking across the entire active UX now that v0.3 functionality is substantially decided.

It supplements `docs/CHATGPT_PROJECT_RUNBOOK.md`, `docs/V0.3_RELEASE_POLISH_PLAN.md`, and `docs/V0.3_INFORMATION_HIERARCHY_POLISH.md`. It does not change canonical catalog, selection, export, source, or Black Pearl behavior by itself.

## 1. Audit goal

Primary screens should maximize the amount of useful EQ content and the actions needed for the current task.

Use these rules consistently:

- one navigation/header treatment per screen, not a global title plus a second in-content back/header;
- bottom navigation belongs to the three top-level destinations, not focused nested workflows;
- persistent screen real estate is for frequent/task-critical actions;
- rare, destructive, explanatory, legal, provenance-link, and advanced actions move to overflow/details/Settings where appropriate;
- explanatory copy appears when it prevents a likely mistake, not as permanent repeated instruction;
- status should be concise and contextual;
- dense does not mean tiny: preserve Material touch targets, dynamic type, TalkBack semantics, and non-color-only state;
- safety-critical Black Pearl confirmation/warning text is not compressed merely to save space.

## 2. App shell and navigation — highest-impact systemic change

### Current issue

Nested screens can show all of the following at once:

1. global top app bar title such as `My EQs`;
2. an in-content `← My EQs` row;
3. a second large screen title such as `Edition XS`;
4. screen-level controls/copy;
5. persistent three-item bottom navigation.

This duplicates navigation and consumes a large fraction of a phone viewport before actual EQ content.

### Proposed rule

Use a single adaptive top app bar:

- top-level roots: `My EQs`, `EQ Library`, `Settings` with no Back arrow;
- nested destinations: Back arrow + current destination title, for example `Edition XS`, `Select EQs`, `Review new EQs`, `Import EQ`, `Hidden EQs`, `About EQ Library`;
- keep active output visible where it is operationally relevant, using the existing compact output label/menu;
- remove in-content breadcrumb/back rows once the app bar owns Back.

Show bottom navigation only on the three top-level roots:

- My EQs root;
- EQ Library root;
- Settings root.

Hide bottom navigation on focused nested screens such as headphone detail, selection editor, new-EQ review, personal import, and Settings subpages. Those screens use app-bar Back and the approved hierarchy.

This both increases usable vertical space and makes the distinction between top-level destinations and focused workflows much clearer.

## 3. My EQs root

### Keep prominent

- active output context;
- headphone rows;
- General EQ rows;
- recovery export state only when recovery is actually required;
- pending new/updated EQ attention on the affected headphone row;
- compact `+ Import` beside Saved snapshots & personal imports.

### Compact

Black Pearl connection must not be a large top-area button. Prefer a compact connection/status treatment such as:

`Black Pearl · Disconnected     Connect`

or an equivalent compact app-bar/status action. Connected/connecting/error state remains visible and accessible.

The normal summary should be a concise line such as:

`4 headphone EQs · 2 General EQs`

Do not add routine explanatory paragraphs when no recovery/error is present.

### Rows

Headphone rows should expose:

- model;
- manufacturer when needed for disambiguation/grouping;
- selected count;
- concise pending attention such as `2 new EQs` / `1 EQ updated` when applicable.

The row tap opens headphone detail. Avoid adding permanent row actions that compete with the primary navigation unless they are genuinely high-frequency.

## 4. Managed headphone detail — major cleanup

### Header

Replace the stacked global `My EQs` title + `← My EQs` breadcrumb + large model block with one nested top bar:

`←  Edition XS                         ⋮`

Use compact supporting metadata immediately below, for example:

`HIFIMAN · 4 selected · 25 available`

### Frequent actions

Use compact actions/status instead of stacked large buttons:

`Black Pearl · Disconnected       Connect`

`Manage EQs`

When pending review exists:

`2 new EQs · Review`

The review callout appears only when there is actual pending attention.

### Per-headphone notification preference

`Notify me about new EQs` remains the approved per-headphone preference, but it does not need to occupy permanent content space. Place it in the headphone overflow/settings surface. The normal detail page only shows pending review attention when needed.

### Destructive action

Move `Remove headphone` out of permanent bottom content into the `⋮` overflow as `Remove from My EQs`, retaining the existing confirmation and optional app-owned-file cleanup behavior.

### EQ rows

Make saved EQ rows denser:

- creator/profile headline;
- one or two compact metadata/summary lines;
- visible selected/output state when useful;
- Favorite star remains directly actionable;
- Black Pearl `Flash` remains directly actionable when Black Pearl is active;
- recovery `Export` appears only when needed;
- `Source` and `Remove preset` may move to a row overflow/details action so attribution remains accessible without a full-width Source button on every row.

Do not hide verification, output compatibility, or source provenance; compress their presentation rather than deleting them.

## 5. EQ Library — Headphones root

The already-approved information-hierarchy cleanup is correct and should remain:

- Headphones / General EQs tabs;
- Search;
- manufacturer/results immediately afterward;
- no permanent OPRA banner/logo/project copy/submission action.

Additional density rule:

- keep search comfortably touchable but avoid oversized vertical padding;
- manufacturer/model list rows use concise count/status lines;
- output explanation stays out of the permanent root viewport.

## 6. Manufacturer/model navigation

Nested manufacturer/model screens use the adaptive app bar instead of an in-content Back row.

Model rows should prioritize:

- model name;
- profile count;
- selected count when already managed.

Avoid repeated explanatory text between navigation levels.

## 7. Headphone profile selection editor — major cleanup

### Current issue

Before the first EQ row, the editor can present:

- in-content Back/breadcrumb;
- product title;
- three large filter buttons;
- active-filter summary;
- History control;
- Select all / Select none;
- a permanent explanatory paragraph about selection/new EQ behavior;
- additional filtered/unavailable status text.

This makes the profiles themselves arrive too late in the viewport.

### Proposed structure

Nested app bar:

`←  Select EQs`

Compact subheading:

`Edition XS · 4 of 25 selected`

Toolbar:

`Filter`   `History`   `Select all`   `None`

The Filter action opens the existing Database / Creator / Target choices. Only active filters appear as compact removable chips/summary. Do not reserve three equal-width filter buttons when no filter is active.

Remove the permanent paragraph explaining that new EQs are not auto-selected; that is now a stable product rule and need not be restated every visit. Retain concise contextual warning/status only when something unusual exists, such as selected archived/unavailable content or active filters hiding rows.

### Completion action

Use a sticky contextual bottom action area while editing, replacing bottom navigation on this nested screen:

`4 selected                         Save`

If zero selected would remove the managed headphone, communicate that at the completion point/confirmation rather than through permanent instructional copy.

Keep the existing dirty Back confirmation.

### Profile rows

Each row should make the checkbox/profile the primary interaction and compact metadata into a predictable pattern. Favorite remains available. Source/Hide can live in compact row actions/overflow/details rather than expanding every row vertically.

## 8. General EQ browse — major cleanup

### Current issue

Search + four category chips + explanatory paragraph + Select all/none row + Save/Hide row can consume most of the first viewport before presets.

### Proposed structure

- Search;
- horizontally scrollable All / Sound / Genre / Utility chips;
- preset list immediately afterward.

Batch selection remains none-selected-by-default, but batch actions become contextual. When one or more rows are checked, show a sticky contextual action area:

`3 selected       Save       Hide`

Select all / None can live in that selection toolbar or compact overflow rather than owning separate permanent rows.

Remove the permanent paragraph explaining that General EQs do not layer with headphone EQs. Keep that rule in details/About/help and surface a warning only if/when a future interaction could actually imply layering.

Keep source/category/verification visible compactly per preset; avoid large source banners.

## 9. New-EQ review

Nested app bar:

`←  Review new EQs`

Compact context:

`Edition XS · 2 new · 1 updated`

Replace the long permanent instruction paragraph with one concise sentence:

`Select new EQs to add. Dismiss keeps them available in EQ Library.`

Back behavior remains unchanged and leaves the batch pending.

Keep review rows none-selected-by-default. Preserve Verified/Unverified labeling, source access, output capability, and changed-tuning state, but present those in compact metadata.

Use a sticky bottom action area:

`Dismiss                         Add selected (2)`

No top-level bottom navigation is shown during review.

## 10. Personal EQ import

### Current issue

The current screen correctly exposes explicit Paste/Choose file, required metadata, raw PEQ text, parsed preview, strict errors, and Save & export, but the permanent technical explanation and large raw-text field can dominate the workflow after a successful parse.

### Proposed structure

Nested app bar:

`←  Import EQ`

Start with the two source actions:

`Paste PEQ text`   `Choose file`

Short format note only:

`Equalizer APO / AutoEq parametric text`

Keep required Manufacturer / Headphone model / EQ name and optional Target/note fields.

Once valid text is loaded, make the parsed canonical preview the primary content. The raw PEQ remains editable but can be placed behind a compact `Edit raw PEQ` expansion after successful parse so the user can inspect/change it without permanently giving 7–14 lines of the viewport to raw text.

Blocking parse errors remain prominent and line-specific.

Use a sticky nested-screen completion action:

`Save & export`

Do not repeat the permanent paragraph about canonical-first conversion/never flashing hardware after the user has a valid preview; preserve that rule in accessible help/details and in any actual output/Flash warning path.

## 11. Settings root — convert from long form to navigation/status hub

Settings is the correct home for configuration, project information, attribution, and feedback, but the root should not become another long documentation page.

Prefer compact sections/rows with current-value summaries:

### Outputs

`Outputs                          5 enabled`

Open a subpage for enabled outputs and per-output options. Black Pearl Direct Flash belongs with Black Pearl output settings rather than consuming a long root description.

### Library

`EQ Library                       1220 profiles`

Supporting line may show last successful refresh. Keep `Refresh now` as compact row/action. Keep:

`Hidden EQs                       12`

### Export

`Export folder                    Documents/EQ Library`

Open/change from a subpage or row action. Keep ownership/move semantics available as secondary explanatory text only when the user is changing the folder.

### Appearance

`Appearance                       System default`

Open System / Light / Dark choices.

### Updates

`App updates                      Up to date · 0.3.0`

Open update actions/status, or expose a compact `Check` action.

### Help & contribute

Keep:

`Feedback & EQ submissions`

### About

Keep:

- `About EQ Library`
- `Data sources & attribution`

This preserves the recently approved source/feedback relocation while stopping Settings root from becoming a permanent wall of descriptions and radio/checkbox controls.

## 12. Settings subpages

### Outputs

Use standard full-width setting rows with checkbox/switch and concise secondary text. Explain output-as-context once at the top of this subpage, not repeatedly elsewhere.

### Hidden EQs

Use the adaptive app bar, compact rows, none selected by default, and a contextual sticky bottom action when selections exist:

`3 selected                       Unhide`

Select all/None can be compact toolbar actions. No Delete action.

### About EQ Library / Data sources & attribution

These are intentionally secondary informational pages, so longer text is acceptable here. Keep them scannable with section headings and compact link rows. No large source artwork is necessary.

## 13. Update banners and transient state

Update/What’s new banners on primary roots should be compact and dismissible so they do not permanently push the user’s EQ content below the fold.

Catalog refresh should keep cached content visible. Use spinner/icon/snackbar/status treatment during normal refresh. Full-screen unavailable/error content is appropriate only when there is genuinely no usable cached catalog yet.

## 14. Dialogs and destructive/safety actions

### Compact ordinary destructive dialogs

Preset/headphone removal dialogs should be concise and retain explicit app-owned-file cleanup choice where applicable.

### Do not compress safety-critical Black Pearl dialogs

Black Pearl Flash confirmation must continue to disclose:

- playback/global-gain adjustment;
- >10-band optimization when applicable;
- outside-validated-range exact-value caution when applicable;
- Cancel / Flash or Flash anyway before any USB write.

Safety disclosure takes priority over density.

## 15. Profile provenance and details

Every profile still preserves creator/source/verification/output information, but not every field requires a permanent full-width action.

Preferred row hierarchy:

1. creator/profile name;
2. compact provenance/verification line;
3. one- or two-line sound/details summary where useful;
4. compact output state;
5. only high-frequency direct actions visible inline.

Source link, Hide/Remove, revision/history detail, and longer provenance may be reached through row overflow/details. This must remain accessible to TalkBack and cannot erase required attribution.

A dedicated full profile-details destination is optional and should not be introduced in v0.3 unless the simpler overflow/compact-row treatment proves insufficient.

## 16. Accessibility guardrails for the density pass

The audit is about reclaiming wasted space, not shrinking interaction targets.

Required guardrails:

- maintain at least Material-recommended touch targets;
- support large font scales without clipping essential actions;
- allow compact action rows/toolbars to wrap or scroll appropriately;
- TalkBack labels identify Favorite, Source, Flash, overflow, selection, and connection state;
- Exact / Optimized / Not exportable, Verified / Unverified, connected/disconnected, and error states are not color-only;
- destructive actions remain explicitly named;
- sticky bottom actions must remain reachable above system navigation/insets;
- nested screens preserve the already-approved system Back behavior.

## 17. Proposed implementation order after approval

1. App-shell adaptive top bar + nested bottom-navigation visibility.
2. Managed headphone detail + shared compact Black Pearl connection treatment.
3. Profile selection editor density/sticky completion.
4. General EQ contextual batch actions.
5. New-EQ review density/sticky actions.
6. Personal import density/raw-text expansion/sticky completion.
7. Settings root/subpage compaction.
8. My EQs root row/status polish.
9. Shared profile-row provenance/action compaction.
10. Accessibility/large-text pass and updated focused Pixel 9 checklist.

Implementation must preserve existing domain/data behavior and must not weaken tests. UI changes invalidate earlier screenshots/candidate APKs and require a fresh exact-head signed candidate plus a focused Pixel 9 UX/regression pass before PR #4 can merge.

## 18. Explicitly unchanged by this audit

- canonical catalog/source ingestion;
- living archive and Hide/Unhide semantics;
- explicit selection/no-auto-selection behavior;
- per-headphone new-EQ notification/review semantics;
- output-specific My EQs membership;
- Add/Save initial export and recovery-only Export semantics;
- SAF ownership/currentness rules;
- conversion/DSP values;
- Black Pearl protocol, preamp/global-gain behavior, Flash safety confirmation requirements;
- no analytics/telemetry/account requirements;
- attribution and non-endorsement requirements.
