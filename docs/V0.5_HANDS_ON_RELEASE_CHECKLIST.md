## Stop conditions

Stop the release-candidate hands-on pass and record the failing step if any of these occurs:

- the v0.5 install requires uninstalling the existing app or clearing user data to launch successfully;
- existing My EQs selections, Favorites, hidden state, personal imports, output settings, or export ownership disappear unexpectedly;
- a normal configuration/lifecycle change loses durable user state or creates duplicate saved state;
- a valid canonical EQ disappears merely because the active output changes;
- file export overwrites/deletes a file EQ Library cannot prove it owns;
- a temporary Storage Access Framework/provider failure is treated as confirmed deletion;
- Add/Save automatically flashes hardware;
- JA11/JM12 are shown as hardware-qualified or JM12 persistence is claimed;
- Black Pearl Direct Flash/Reset controls write anything after a confirmation is cancelled;
- the app crashes, hangs indefinitely, or enters an unrecoverable navigation/USB/storage state.

2. Launch EQ Library.

## 2. Navigation and basic lifecycle

1. Start at **My EQs**.
2. Open **EQ Library**, drill into a manufacturer/model, then use Android Back. Confirm Back unwinds the in-app hierarchy rather than jumping unpredictably or exiting early.
3. From the EQ Library root, press Back and confirm it returns to My EQs.
4. Open **Settings** and press Back; confirm it returns to My EQs.
5. From the My EQs root, confirm Back exits normally.
6. Reopen the app, background it for a short period, then return. Confirm the current screen/state remains coherent and no duplicate navigation layer appears.
7. If auto-rotate is enabled on the Pixel 9, rotate once on a non-destructive screen and confirm the app remains stable.

**Pass:** navigation/back/lifecycle behavior is stable after the MAD refactor.

## 3. Unsaved selection state across recreation

1. Open its profile-selection editor.
2. Change one or more checkboxes but **do not save yet**.
3. Background/foreground the app. If practical, also rotate once with auto-rotate enabled.
4. Confirm the unsaved checkbox choices are still present.
5. Confirm **Select all** and **Select none** behave correctly.
6. Back out without saving and confirm durable My EQs membership did not silently change.
7. Re-enter, make a deliberate selection, Save/Add, and confirm only the intended profiles become managed for the active output.

Repeat the same basic unsaved-state recreation check once for a General EQ batch-selection surface if available.

**Pass:** transient editor state survives recreation when expected, while durable state changes only after explicit save/add actions.

## 6. Fidelity/reason presentation

Use several profiles/output combinations that exercise different states when available.

1. Find at least one profile shown as **Exact** and confirm its concise reason indicates source values are preserved.
2. Find an **Optimized** finite-target case and confirm the reason distinguishes native rounding, full-response fitting, generated headroom, or the applicable combination rather than using a generic misleading message.
3. If a source exceeds a finite hardware band budget, confirm the UI describes complete-response adaptation and does **not** say it merely took the first N bands.
4. Find or construct a Not suitable / Not exportable case and confirm the action that would produce an invalid target is disabled/unavailable rather than silently clamping/dropping data.

**Pass:** Exact/Optimized/Not suitable presentation matches the actual target representation semantics.

## 8. Additional file-output smoke

A full third-party-app qualification is not required for every target in this focused Pixel 9 pass. The goal is to prove correct output selection, deterministic file generation, and storage ownership behavior.

Exercise at least three additional file outputs, including **TOPPING Tune** and at least one GraphicEQ target:

1. Select the output.
2. Add/Save or Export a known profile.
3. Confirm the file type/name/location match the selected output rather than a previous output context.
4. Open the exported text/XML and confirm it is non-empty and structurally appropriate for the selected target.
5. For TOPPING Tune, confirm the UI reports Optimized rather than claiming unverified Exact downstream hardware precision.
6. For Wavelet or AutoEq GraphicEQ, confirm the file contains the expected 127-point GraphicEQ-style response representation.
7. Switch outputs repeatedly and confirm My EQs/export state remains output-specific rather than leaking between targets.

**Pass:** output routing and file generation remain isolated and coherent across the expanded registry.

## 9. Storage Access Framework ownership/recovery smoke

Use a disposable test profile/file where practical.

1. Export a file through EQ Library and record the actual filename Android/provider returns.
2. Confirm EQ Library recognizes its own exported file as current.
3. Create or place an unrelated file with a similar/same desired filename if the provider permits a safe test.
4. Confirm EQ Library does not overwrite or delete the unrelated file merely because the names collide.
5. Temporarily make the export provider/folder unavailable if this can be done safely (for example, revoke/unmount an external provider rather than deleting the file).
6. Return to EQ Library and confirm the temporary lookup failure is treated as unavailable/recoverable, not as proof the owned file was deleted.
7. Restore access and confirm the app can recover normal ownership/currentness behavior.

Skip steps that cannot be performed safely with the chosen provider; record them as not exercised rather than forcing a destructive storage test.

**Pass:** provider failure is distinct from confirmed absence and unrelated files are never treated as app-owned.

## 10. Black Pearl non-destructive MAD/lifecycle smoke

**Pass:** MAD lifecycle ownership does not regress the already-qualified Black Pearl connection/write-gate behavior.
