# EQ Library v0.6 — DEVICE UX polish decisions

Status: **Approved 2026-09-14**. This is a later product decision and therefore supersedes conflicting wording in older v0.6 planning text. Read it with `docs/V0.6_MY_DAC_APPROVED_DESIGN.md`, `docs/V0.6_MY_DAC_IMPLEMENTATION_PLAN.md`, and `docs/V0.6_MY_DAC_STATUS.md`.

## Goal

Keep My DAC -> DEVICE visually minimal while making state changes understandable and keeping the interaction model reusable across TRN Black Pearl, FiiO JA11, and future supported DACs.

The common UI must be capability-driven. Device-specific adapters retain exact units, commands, ranges, reset semantics, and validation status; the shared UI must not project one DAC's behavior onto another.

## Volume presentation

Ordinary playback volume is presented in the unit users naturally expect for the exact device.

- **TRN Black Pearl:** show ordinary volume as percentage only, for example `Volume · 63%`. Do not expose the protocol dB/raw register as the normal DEVICE volume mental model.
- **FiiO JA11:** retain its independently established native `0..60` device level. Do not convert it to Black Pearl percentage or dB semantics.
- **Future DACs:** declare the correct presentation unit per exact device capability.

For Black Pearl, the underlying DEVICE transaction remains the already conservative whole-dB native protocol step. The percentage UI is presentation only and must not weaken validation or invent finer writes.

After a verified Apply, fresh hardware readback becomes the new current volume. No user-visible delta is retained from the volume that happened to be present when the screen was first opened.

EQ preamp/headroom tracking remains separate internal state and must never be presented as the ordinary DEVICE volume baseline.

## Output wording

Replace the ambiguous user-facing `Normal / manual output` concept with **Default EQ target**.

Settings wording:

- **Automatic (recommended):** `Use a connected supported DAC when one is available. Otherwise use your Default EQ target.`
- **Manual:** `Always use your Default EQ target, even when a supported DAC is connected.`
- **Default EQ target:** the saved target used in Manual mode and when Automatic has no single supported DAC to use.

Also explain once, concisely:

`This controls how EQs are prepared, exported, and flashed. It does not change Android's audio output.`

The underlying Automatic/Manual resolution behavior is unchanged.

## DEVICE operation feedback

Routine DEVICE changes use one shared status pattern across supported DACs:

1. user confirms or applies the requested value;
2. the editor closes;
3. the DEVICE status area shows `Applying <setting>…` while the transaction/readback is in progress;
4. verified success briefly shows `<Setting> updated ✓`;
5. a failure must show a concise truthful error/current-state message and must never present requested local state as current.

A normal active transaction must not simultaneously show `Last read` / `Reconnect or refresh…` merely because the pre-write snapshot is deliberately marked non-current during verification.

For a control that intentionally requires USB restart/re-enumeration, `Applying…` remains visible until a replacement session and fresh read verify the requested state.

This presentation is generic; transaction safety stays device-specific and unchanged underneath.

## Reset device — approved common UX

A supported DAC may expose a bottom-of-DEVICE reset section only when the action has an exact, truthful device-specific contract. A **factory reset** claim requires independently established factory/default semantics. A separately defined app-owned restore preset may use the same compact interaction pattern only when its values and provenance are stated truthfully and it is not mislabeled as factory state.

For a verified factory-reset capability, the common wording remains:

Main DEVICE page:

**Reset device**  
`Restore supported <device> settings to their factory defaults.`

Action: **Reset to factory defaults**

Keep this section visually simple: ordinary divider/heading/description/action, not a large warning card or technical checklist.

Confirmation dialog:

**Reset to factory defaults?**

`This will restore supported <device> settings to their verified factory defaults. Listening volume may change.`

Optional checkbox, OFF by default, only when the exact device supports a separately verified EQ reset:

`Also reset EQ to flat`

`Your saved EQs in EQ Library are not affected.`

Actions: **Cancel** / **Reset**.

Progress uses the same shared DEVICE status language. Partial/uncertain reset must not be called successful.

`Reset EQ to flat` remains independently available on the EQ tab where supported.

## Later Black Pearl owner decision — EQ Library restore defaults

The project owner subsequently approved an explicit Black Pearl **EQ Library restore preset** even though the research does not establish a complete TRN factory-default contract. This is a later product decision and supersedes the earlier Black Pearl-specific instruction to hide all whole-device restore UI.

The action must use app-owned wording rather than a factory claim:

Main DEVICE page:

**Reset device**  
`Restore EQ Library's Black Pearl defaults. This does not change microphone gain or your saved EQs.`

Action: **Restore defaults**

Confirmation:

**Restore Black Pearl defaults?**

The dialog must state the selected targets plainly:

- Volume: **50% presentation**;
- DAC filter: **FAST-LL**;
- Gain: **HIGH**;
- Amplifier: **CLASS AB**;
- Balance: **Centered**;
- Microphone gain: **unchanged**.

It must also warn that listening volume may change.

Retain the optional checkbox, OFF by default:

`Also reset EQ to flat`

`Your saved EQs in EQ Library are not affected.`

Actions remain **Cancel** / **Reset**.

The optional EQ reset must reuse the independently qualified Reset EQ to flat transaction. The DEVICE restore must reuse the existing qualified individual setting-write/persist/readback path, stop on any unverified step, never automatically retry a setting write, and not claim success until all requested targets are verified. The exact transaction/safety plan is maintained in `docs/BLACK_PEARL_V0.6_FACTORY_DEFAULTS_RESEARCH.md`.

Passing the focused hardware checklist qualifies this **EQ Library restore preset** only. It does not convert the selected values into evidence of TRN factory state.

## Capability rule for future DACs

Factory reset is a declared capability, not a universal assumption. A future FiiO or other DAC may implement reset using a dedicated vendor command, a verified group of individual settings, or may not expose reset at all. A future app-owned restore preset likewise needs an explicit model-specific contract and truthful wording.

Do not share or infer factory-default values across models or firmware revisions. Do not label a third-party controller's convenience preset—or EQ Library's own selected preset—as a hardware factory reset without corroboration.
