# EQ Library v0.6.0 — My EQs ownership and Needs attention recovery

Status: **Current authority for v0.6 library ownership/recovery behavior.**

This document records the later project-owner decisions that supersede older wording which described My EQs membership as output-specific. Read it with `docs/CHATGPT_PROJECT_RUNBOOK.md`, `docs/ARCHITECTURE.md`, and the current v0.6 My DAC documents. Where older architecture/planning text conflicts, this document and the runbook win.

## 1. My EQs is device-agnostic

My EQs is one local library of headphones/EQs the user has chosen to keep. Its identity does not change when the active export/flash target changes.

The following are global/local-library ownership state:

- managed headphones and their selected canonical profiles;
- Favorites;
- Personal EQ imports;
- DAC-captured Personal EQs;
- General EQs;
- review/notification state tied to those library items.

Changing the active output may change compatibility, fidelity, target-derived representation, export currentness, available file actions, connection controls, or Flash availability. It must not silently add/remove My EQs entries, change canonical selections, or close an open My EQ detail merely because the target changed.

Legacy `outputId` arguments and output-selection Room tables may remain temporarily for migration/source compatibility. Current repositories deliberately treat those IDs as non-owning compatibility parameters. They must not be reintroduced as current membership filters.

## 2. Save, Export, and Flash are separate actions

**Save / Add to My EQs** changes local library state only.

It does not implicitly:

- export files;
- open the system folder picker;
- download anything;
- Flash a DAC;
- imply persistence to hardware.

**Export** explicitly derives the chosen target representation and writes app-owned files through the Storage Access Framework.

**Flash** explicitly derives the connected hardware representation and runs the qualified device transaction.

Target-specific representations/currentness are derived state. They never become the identity of the saved EQ.

## 3. DAC capture is provenance, not ownership

A verified hardware EQ captured from My DAC becomes a normal Personal EQ. The source DAC/model is retained as provenance, but the captured EQ is not owned by that device and remains visible in My EQs when no DAC is connected or when another target is selected.

If a capture exactly matches an existing saved EQ, link to the existing identity instead of creating a duplicate when the maintained matching contract permits it.

## 4. Needs attention

An app-managed persisted artifact must not become invisible merely because current library identity cannot be resolved confidently.

`Needs attention` is the persistent recovery surface for app-owned/persisted-access artifacts recorded in export ownership state that no longer have a confident current My EQ association.

Current v0.6 implementation derives unresolved items from persisted `export_ownership` records. It does **not** crawl arbitrary user storage.

Required behavior:

- unresolved artifacts survive restart/rescan while their ownership record remains;
- each exact owned document URI appears at most once;
- target/destination changes do not create false unresolved items;
- provider/permission unavailability keeps the artifact visible rather than treating it as missing;
- confirmed missing documents may have stale ownership forgotten according to the existing storage policy;
- malformed/unsupported files remain visible but are not falsely recoverable.

## 5. Recovery contract

Recovery is intentionally conservative.

A file may become a Personal EQ only when strict parsing establishes a supported parametric EQ without silently dropping unsupported filters or values. The user supplies any missing Manufacturer, Model, and EQ name needed to create the local item.

Recovery preserves:

- parsed preamp;
- supported filter type;
- frequency;
- gain;
- Q;
- slope where represented;
- original-file provenance.

Recovered content is stored as a normal device-agnostic Personal EQ.

Current supported recovery input includes strict EQ Library personal-parametric text and deterministic EQ Library UAPP/ToneBoosters XML that can be decoded safely. GraphicEQ and malformed/incomplete material are not silently converted.

## 6. Deletion boundary

Recovery cleanup may delete only the exact app-owned document represented by the persisted ownership URI and only through the existing SAF ownership path.

Never recursively delete arbitrary folders, crawl unrelated external files, or infer that a provider failure means the document is gone.

Deleting an unresolved artifact is an explicit user action with confirmation. Removing an ownership record alone is permitted only when the storage layer has positively established that the owned document is missing.

## 7. Current implementation notes

As of the v0.6 branch refactor:

- `ManagedHeadphonesRepository` reads/writes shared managed rows for current ownership;
- `SavedEqRepository` reads/writes global Favorites/Personal EQs;
- `SavedGeneralEqRepository` reads/writes global General EQs;
- legacy per-output selection tables remain migration/history state but do not drive current My EQs visibility;
- `UnclaimedEqRepository` derives `Needs attention` from persisted export ownership and strict parsing;
- `UnclaimedEqOwnershipPolicyTest` covers global claimed/unclaimed behavior, destination-independence, exact-URI uniqueness, visibility of distinct unresolved documents, and recovered-value/provenance preservation;
- saving managed selections, Personal EQs, review additions, and General EQs no longer auto-exports;
- changing the active output no longer clears the currently open managed-headphone detail.

`EqLibraryViewModel` may still pass an active `outputId` through compatibility-shaped repository calls and tag target-derived currentness with the active output. Because the repositories above deliberately ignore that ID for ownership, this is compatibility/action-context plumbing only. Future cleanup may simplify those signatures, but must not restore output-scoped membership.

## 8. Validation rule

Any future change in this area must prove all of the following:

1. My EQs contents remain identical across target changes.
2. Exact profile selections remain identical across target changes.
3. Save/Add never exports or Flashes without a separate explicit action.
4. Target compatibility/fidelity/currentness can still change independently.
5. unresolved app-owned artifacts remain visible across restart/rescan until resolved or positively missing.
6. recovery never silently accepts unsupported filters or arbitrary external files.
7. exact app-owned deletion boundaries remain enforced.
