## Remaining normal DEVICE controls

The first consolidated candidate `a3837779b5b732f3b388f80a86c0b14fc00e34c5` was stopped after physical testing exposed delayed amp-topology visibility and unreliable `0.5 dB` normal playback steps. The app correctly reported mismatch instead of false success; the owner restored the Black Pearl reference state.

Replacement behavior `001b5ea5b2199784cfc8cf34941b018bf927caa1` fixed whole-dB playback staging and added bounded same-session post-write settling reads. It passed its automated/signing gates, but it is now **superseded before physical retest** by the additional UAC-readout and read-transport reliability work. Do not use `001b5ea...` as the next hands-on candidate.

Active reliability behavior being validated now:

- Black Pearl USB operations remain serialized by the existing transport mutex;
- a nondestructive Black Pearl READ that times out may be reissued **once** in the same USB session;
- a session replacement stops retry immediately;
- setting writes are never retried/resubmitted by this mechanism;
- normal playback DEVICE changes remain conservative whole-dB steps, while the lower-level protocol stays 1/256 dB;
- balance retains the existing conservative 50 ms spacing between left/right writes;
- candidate post-write verification still requires exact target readback and unchanged unrelated state.

## USB audio mode

- **UAC 1.0/2.0 current-mode detection is implemented** from standard USB AudioControl descriptors and appears under DEVICE -> USB / System.
- UAC mode remains **read-only** because no exact Black Pearl software switching command has been established.
- Review of `Matr1x01/trnBlackPearlEq@f289230...` adds independent corroboration for the known normal-control command map but also contains **no software UAC command**.
- No speculative probing or borrowed related-device command will be used.

## Work-item changes from external reference review

- **Add later:** real-time physical volume-button synchronization; the reference demonstrates unsolicited volume-event handling, but this is a separate product behavior and is not part of the current qualification candidate.
- **Defer:** a general **Save device settings** action until transient live controls pass and persistence is separately qualified by actual power-cycle testing. Do not infer persistence from a successful host write/readback alone.
- **Keep:** explicit Review -> Apply -> verified readback, no cached-state replay, no setting-write retry, no generic Save-to-Flash in current DEVICE transactions, firmware read-only.
