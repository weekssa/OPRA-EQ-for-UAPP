## Implemented v0.6 My DAC behavior

### Session / navigation

- supported-DAC recognition is separate from USB connection state;
- My DAC appears immediately beside My EQs after a supported DAC is recognized;
- My DAC remains available for the current app session after disconnect and shows stale/Last-read state instead of making navigation jump;
- supported USB attach uses Android's normal permission/default-app flow;
- an already-open app uses the nonblocking **Open My DAC** prompt;
- connected-DAC context does not silently change the separate global active output.

### EQ state

- read-only native hardware EQ snapshots;
- deterministic Black Pearl native fingerprints;
- Flat / Exact / ambiguous Exact / Unknown matching;
- Modified lineage only after a verified in-app edit that began from a known saved representation;
- reconnect or any outside native change invalidates Modified lineage back to Unknown;
- ordinary Black Pearl playback/global gain is not used to invent EQ/source identity.

### Visual EQ / editor

- deterministic combined-response graph;
- compact read-only hardware graph and larger editor graph;
- tap-only band selection; graph dragging never edits or writes hardware;
- exact frequency/gain/Q entry and supported filter-type selection;
- All Bands view;
- deterministic headroom assessment from the complete planned response;
- separate blocking device limits, caution range, and headroom status;
- Review before Apply;
- fresh-baseline checks, safe gain ordering, device write, readback, and verification;
- requested local state is never reported as current hardware until verification succeeds.

### My DAC EQ actions

- **Change EQ** uses the Black Pearl-specific My EQs collection rather than the unrelated global active-output collection;
- candidates show deterministic Exact / Optimized / Not suitable status;
- selection opens an explicit Flash review; it never writes immediately;
- **Edit EQ** uses the verified editor/apply transaction;
- **Save DAC EQ** captures current native state as a Personal EQ with capture provenance and optional real headphone association or intentional unassociated state;
- exact existing matches link instead of creating duplicates;
- **Reset EQ to flat** is a secondary confirmed action that reuses the already-qualified Black Pearl reset transaction and does not arbitrarily reset ordinary playback volume.

### DEVICE architecture

- `DacControlRepository` remains separate from `HardwareEqRepository`;
- Compose receives typed capability/presentation state and contains no protocol constants;
- unqualified DEVICE controls are structurally absent rather than exposed as speculative controls;
- Black Pearl has a dedicated **Hardware qualification · read-only** panel for:
  - firmware/version;
  - DAC reconstruction filter;
  - gain mode;
  - amplifier topology;
  - microphone gain;
  - left/right balance;
  - playback/global gain;
- all candidate fields must be read successfully from one current session or the qualification read fails;
- no new DEVICE write control is production-exposed.

## Still blocked / intentionally absent

The following remain unqualified and must not be exposed as normal write-capable DEVICE controls merely because reads work:

- DAC reconstruction-filter writes;
- gain-mode writes;
- amplifier-topology writes;
- balance writes;
- microphone-gain writes;
- playback/global-gain DEVICE writes;
- cached-state restore on reconnect;
- firmware/bootloader/cross-flash writes;
- raw register console or USB identity mutation.

FiiO JA11 and stock JCALLY JM12 remain hardware-validation pending.
