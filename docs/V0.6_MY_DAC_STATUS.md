## Current product direction

The project owner approved the next v0.6 build cycle on 2026-09-13 and authorized aggressive autonomous development.

Current device roadmap:

**TRN Black Pearl → FiiO**

JCALLY is no longer part of the active/current/upcoming product. Useful historical protocol and safety research may remain internally, but normal users must not see JCALLY as supported, pending, planned, experimental, or coming soon. A connected JCALLY device must follow the normal unsupported/unrecognized-device path.

The approved visual direction replaces the prior purple identity with the TOPPING-reference blue `#257BFF` (`RGB 37, 123, 255`) while preserving semantic error, warning, success, and disabled colors.

The approved Black Pearl objective is full normal day-to-day DAC management as far as independently established and safely qualified. Software work may implement the complete normal-control framework, but each new physical write graduates independently. Planned qualification order is:

`DAC filter → balance → microphone gain → amp topology → gain mode → playback volume`

Firmware remains read-only. Firmware/bootloader/cross-flash, raw-register consoles, USB identity mutation, cached-state restoration, and speculative persistence remain prohibited.

## Implemented v0.6 My DAC behavior

### Session / navigation

- supported-DAC recognition is separate from USB connection state;
- My DAC appears immediately beside My EQs after a supported DAC is recognized;
- My DAC remains available for the current app session after disconnect and shows stale/Last-read state instead of making navigation jump;
- supported USB attach uses Android's normal permission/default-app flow;
- an already-open app uses the nonblocking **Open My DAC** prompt;
- connected-DAC context does not silently change the separate global active output.

### EQ state and editing

- read-only native Black Pearl hardware EQ snapshots;
- deterministic native fingerprints and Flat / Exact / ambiguous Exact / Unknown matching;
- Modified lineage only after a verified in-app edit that began from a known saved representation;
- reconnect or outside native change invalidates Modified lineage back to Unknown;
- compact and editor response graphs with tap-only band selection;
- exact filter type/frequency/gain/Q editing and All Bands view;
- deterministic complete-response headroom assessment;
- Review before Apply;
- fresh-baseline checks, safe gain ordering, write, readback, and verification;
- Save DAC EQ as a Personal EQ with capture provenance and optional real headphone association;
- Change EQ from the Black Pearl-specific My EQs collection with Exact / Optimized / Not suitable status;
- Reset EQ to flat through the already-qualified transaction.

### DEVICE architecture

- `DacControlRepository` remains separate from `HardwareEqRepository`;
- Compose receives typed capability/presentation state and contains no USB request/register constants;
- Black Pearl DEVICE state covers firmware, DAC filter, gain mode, amp topology, mic gain, balance, and playback/global gain;
- all fields must be read successfully from one current session or the complete snapshot fails;
- stale/replacement USB sessions are never promoted to current merely because the device reconnects;
- the generic Black Pearl write transaction requires a current expected session, takes a complete fresh baseline, writes only the requested control, performs complete readback, verifies the exact requested result, rejects unrelated-state changes, and never invokes the generic flash/save command;
- only the control currently admitted by `BlackPearlDeviceQualificationPolicy.candidateWriteControlIds` may be product-write-interactive.
