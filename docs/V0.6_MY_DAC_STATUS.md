## Connected-DAC UX state

The owner-approved simplified My DAC model is implemented:

- one shared ViewModel-scoped supported-DAC session across My EQs, My DAC and EQ Library;
- automatic fresh EQ + DEVICE reads after connection/reconnection;
- automatic state refresh after successful Flash/reset/editor Apply/DEVICE writes;
- session-sticky My DAC navigation after disconnect;
- automatic physical reattach after one successful connection in the current app/ViewModel lifetime;
- no second My DAC connection/read ceremony during normal navigation;
- no My DAC **Change EQ** chooser;
- Flash from **My EQs** or directly from a compatible **EQ Library** profile when exactly one supported DAC session is connected;
- no guessing when more than one supported DAC is connected;
- Black Pearl DEVICE is one concise current-value settings list with row-level editing and only short level-sensitive confirmations;
- Black Pearl ordinary playback is shown as percentage-first **Volume**;
- Black Pearl UAC mode remains read-only with the approved manual UAC 1.0/2.0 startup instructions;
- FiiO JA11 uses the same shared session/status architecture while retaining its own established native semantics.

The transaction layer still owns fresh baseline/session/readback protection, target-only writes, unrelated-state verification, no write retry, and truthful failure reporting. Reconnect opens and reads a fresh replacement session; it does not push cached EQ or DEVICE values back to hardware.

## Device-agnostic My EQs / recovery refactor

The later project-owner library decision is implemented and documented in `docs/V0.6_LIBRARY_OWNERSHIP_AND_RECOVERY.md`:

- My EQs ownership and profile selection are global/device-agnostic;
- active output changes compatibility, derived representation/currentness, Export and Flash behavior only;
- Favorites, Personal EQs, DAC captures, and General EQs remain the same local items across target changes;
- saving/adding to My EQs does not automatically Export or Flash;
- DAC capture uses the DAC only as provenance and becomes a normal Personal EQ;
- changing the active output no longer closes the open managed-headphone detail;
- persistent **Needs attention** derives unresolved exact app-owned artifacts from export ownership rather than crawling arbitrary storage;
- strict recovery preserves supported PEQ values and original-file provenance, while malformed/unsupported artifacts remain visible but not falsely recoverable;
- exact app-owned SAF deletion boundaries are preserved.

Legacy per-output tables and `outputId` repository signatures may remain temporarily for migration/source compatibility, but they no longer decide current My EQs visibility or identity.

## Current software state

The Black Pearl Restore-defaults behavior is implemented and physically qualified on the exact signed `b0340842` candidate.

The implementation deliberately:

- lowers Black Pearl playback to a conservative qualified minimum before level-sensitive restore writes;
- routes every selected target through the normal verified DEVICE path, with already-matching values allowed to resolve as verified no-ops;
- stops on stale session, transfer failure, readback mismatch, unrelated-state change, or other verification failure;
- never automatically retries a setting write;
- restores microphone gain to **0 dB**;
- restores the final whole-dB playback setting that displays as **50%**;
- keeps EQ flattening optional and separate.

The device-agnostic My EQs / Needs attention work remains software-validated and documented. No hardware behavior was added to those library changes.
