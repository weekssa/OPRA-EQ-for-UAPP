## Connected-DAC UX state

The owner-approved simplified My DAC model is implemented:

- one shared ViewModel-scoped supported-DAC session across My EQs, My DAC and EQ Library;
- automatic fresh EQ + DEVICE reads after connection/reconnection;
- automatic state refresh after successful Flash/reset/editor Apply/DEVICE writes;
- no second My DAC connection/read ceremony during normal navigation;
- no My DAC **Change EQ** chooser;
- Flash from **My EQs** or directly from a compatible **EQ Library** profile when exactly one supported DAC session is connected;
- no guessing when more than one supported DAC is connected;
- Black Pearl DEVICE is one concise current-value settings list with row-level editing and only short level-sensitive confirmations;
- Black Pearl UAC mode remains read-only with the approved manual UAC 1.0/2.0 startup instructions;
- FiiO JA11 uses the same My EQs / EQ Library ownership model rather than a second EQ chooser in My DAC.

The transaction layer still owns fresh baseline/session/readback protection, target-only writes, unrelated-state verification, no write retry, and truthful failure reporting.

## Owner-reviewed DEVICE polish

The first finished-UX signed candidate, behavior source `f32b9c3a81f77a8650f1b6f730e4a4c9171310ad`, passed the automated/signing gates and the owner then reviewed the DEVICE UI on Pixel 9 / TRN Black Pearl. The shared connection/read presentation looked correct, but that hands-on review identified three usability refinements before continuing the destructive regression:

1. Black Pearl ordinary volume should be percentage-first rather than exposing the native dB register as the normal user mental model.
2. `Normal / manual output` should be renamed/explained as **Default EQ target**.
3. routine DEVICE Apply should visibly progress through **Applying… -> <Setting> updated ✓** or a truthful failure instead of appearing to flash silently.

Those refinements are now implemented in the branch code. The behavior-changing polish source is:

`0926a83eca55287dabbb7158d49a654d4f7957a6`

Current behavior:

- Black Pearl row is **Volume · N%**; ordinary DEVICE UI no longer shows the raw/dB register as the volume baseline;
- the volume editor is percentage-first while the already-conservative whole-dB native write step remains internal;
- after verified Apply, fresh hardware readback is the new current volume rather than a retained delta from the value present when the screen opened;
- FiiO JA11 keeps its established native `0..60` level rather than inheriting Black Pearl percentage semantics;
- Settings uses **Default EQ target** and explains that it controls EQ preparation/export/Flash, not Android audio routing;
- Black Pearl and FiiO share a reusable DEVICE operation-status presentation;
- an active transaction shows **Applying <setting>…** instead of simultaneously showing stale `Last read` wording;
- verified routine success briefly shows **<Setting> updated ✓**;
- restart-sensitive FiiO controls stay in Applying state until replacement-session verification.

Documentation-only commits after `0926a83e...` do not change that behavior.

## Reset-device UX and evidence gate

The owner approved a generic, capability-driven **Reset device** pattern for future supported DACs:

- main DEVICE page stays minimal: heading `Reset device`, one sentence, and `Reset to factory defaults`;
- confirmation may offer **Also reset EQ to flat** OFF by default only when the exact device supports an independently verified EQ reset;
- success is shown only after the complete reset is verified;
- the same shared UX may be used by Black Pearl, FiiO, or future DACs while each model keeps its own exact reset implementation and defaults.

This action is **not currently exposed for Black Pearl**. Research recorded in `docs/BLACK_PEARL_V0.6_FACTORY_DEFAULTS_RESEARCH.md` found no sufficiently established exact factory-reset command/default table. A third-party controller's convenience `Factory Reset` sequence conflicts with independent reports of shipped/initial Black Pearl gain/topology and does not establish every supported control. Therefore EQ Library does not guess factory defaults from that sequence or from the project's qualification baseline.

FiiO or future models receive the same reset UI only after their exact reset/default semantics are established.

## Manual Black Pearl UAC behavior

The app detects the actual current UAC mode from standard USB AudioControl descriptors. No safe Black Pearl software/HID UAC switch command is established.

The approved helper text uses the established manual startup behavior:

- **UAC 1.0:** disconnect the Black Pearl, leave headphones connected, hold **+** and **−**, reconnect USB, then release after the DAC powers/enumerates;
- **UAC 2.0:** reconnect normally without holding the buttons;
- EQ Library automatically reads and displays the active mode from the replacement USB session.

The detected descriptor state remains authoritative for hardware/firmware revisions where button behavior differs.
