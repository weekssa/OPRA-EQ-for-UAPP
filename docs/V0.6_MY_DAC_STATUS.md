## Approved UX simplification — implementation in progress

After physical use exposed navigation friction, the owner approved a simpler finished-product interaction model:

- one shared supported-DAC connection/session for My EQs, My DAC and EQ Library;
- automatic fresh EQ + DEVICE read on connection/reconnection;
- automatic refresh after successful Flash/reset/editor Apply/DEVICE write;
- no redundant second My DAC Connect/Read step during ordinary use;
- remove the unusable My DAC **Change EQ** chooser;
- Flash from **My EQs** or directly from **EQ Library** instead;
- remove duplicate DEVICE overview/current-values sections;
- each editable DEVICE row shows the current value and is itself the edit affordance;
- routine qualified selections apply immediately and verify readback without protocol-heavy review dialogs;
- retain only short plain-language confirmation where a level-sensitive change genuinely warrants it;
- keep UAC mode read-only but show a concise manual Black Pearl UAC switch/startup sequence directly under the row;
- do not add a generic Save-device-settings or Restore-defaults control without exact device semantics.

The transaction layer must retain fresh baseline/session/readback protection, unchanged unrelated-state verification, no write retry, and truthful failure reporting. The simplification is presentation/workflow work, not a weakening of safety.

## Manual Black Pearl UAC behavior

The app detects the actual current UAC mode from standard USB AudioControl descriptors. No safe Black Pearl software/HID UAC switch command is established.

The approved helper text uses the established manual startup behavior:

- **UAC 1.0:** disconnect the Black Pearl, leave headphones connected, hold **+** and **−**, reconnect USB, then release after the DAC powers/enumerates;
- **UAC 2.0:** reconnect normally without holding the buttons;
- EQ Library then automatically reads and displays the active mode from the replacement USB session.

The detected descriptor state remains authoritative for hardware/firmware revisions where button behavior differs.
