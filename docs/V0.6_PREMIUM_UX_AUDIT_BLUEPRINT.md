# v0.6 Premium UX audit and blueprint

**Status: APPROVED / IMPLEMENTATION IN PROGRESS**

This document records the approved premium visual/interaction direction for v0.6. The project owner explicitly approved this blueprint on 2026-09-14. Implementation must preserve the qualified behavior and hardware-safety contracts in the runbook, architecture, device qualification records, and approved v0.6 design documents.

The first premium checkpoint was physically reviewed by the project owner on a Pixel 9 with a TRN Black Pearl using exact signed source `b952aed8d410fe215ac38292d035aec1b16ee2ef` and was reported **PASS**. Evidence category: **OWNER-REPORTED**. Remaining work in this blueprint may continue without another design approval so long as it stays within this approved direction and does not invent new hardware behavior.

## Product intent

EQ Library should feel like a focused Android audio tool rather than a collection of implementation surfaces. The interface should combine:

- Material 3 Android interaction conventions;
- Apple-like restraint in visual hierarchy and information density;
- clear, direct device controls;
- progressive disclosure instead of repeated explanatory copy;
- stable, obvious state and action feedback;
- source-agnostic EQ-library behavior.

The redesign must not change these core product contracts:

- My EQs ownership is global and device/output-agnostic.
- Target is action context, not an ownership filter.
- One supported-DAC connection/session is shared across My EQs, My DAC, and EQ Library.
- Flash/apply belongs on the EQ item/detail where the user chooses the EQ; My DAC does not add a second EQ chooser.
- DEVICE controls only expose verified capabilities and use existing qualified read/write semantics.
- EQ editing remains staged until Review / Apply or Discard.
- Saving an EQ does not imply export or hardware flash.
- Hardware state and library state remain distinct.

## Navigation

Keep the four primary destinations:

- **My EQs**
- **My DAC** — visible when a supported DAC is present for the session
- **EQ Library**
- **Settings**

These labels describe places, not implementation layers. Avoid adding secondary destinations for actions that belong inside an existing place.

### My DAC hierarchy

My DAC should feel like one device surface:

1. device identity + concise connection state;
2. sibling **EQ | DEVICE** controls;
3. content for the selected area.

Do not recreate separate Overview → Device Settings → Edit Settings layers that repeat the same current values.

### EQ actions

Users apply/flash EQ directly from My EQs or EQ Library. My DAC reports and edits the EQ already on the connected DAC; it is not a second browser/chooser.

## Top bars and Target

### Target is secondary action context

The selected output target affects compatibility and available Export/Flash actions. It must never visually suggest that changing it changes which EQs the user owns.

Preferred presentation on My EQs and EQ Library:

`Target: Black Pearl  ▾`

This should be visually quieter than the screen title and search/browse content. It can live just below the top app bar or in another clearly secondary action-context position.

Changing Target must:

- retain the current My EQs / EQ Library screen;
- retain an open managed-headphone detail;
- retain ownership/favorites/personal EQs;
- update compatibility/currentness/action availability only;
- remain a temporary session action context when changed from My EQs / EQ Library;
- not silently rewrite Settings → Automatic/Manual or the saved default target.

Settings remains the place for durable default-output behavior.

## My DAC

### Device identity / connection

Show the device once, prominently enough to orient the user but without consuming a large card.

Example:

**TRN Black Pearl**  
Connected

Connection controls only appear when they are actionable: Connect, Retry, or a compact failure state. Do not show redundant Connect/Read/Refresh controls while a healthy shared session already owns fresh state.

Fresh reads happen automatically on connection/reconnection and after affected writes. Manual Refresh may remain available as a secondary recovery action where appropriate.

### EQ tab

Information order:

1. **Current EQ** or **Last read EQ**
2. profile identity / Flat / Custom / Unrecognized state
3. response graph where useful
4. primary actions
5. concise metadata/attribution

Action order:

- **Edit EQ**
- **Save as Personal EQ** when meaningful
- **Reset EQ to flat**

Avoid card-on-card nesting. Use typography, spacing, and dividers rather than multiple elevated containers.

### DEVICE tab

Use grouped settings rows with current state visible inline:

`Volume ................................ 50%`
`DAC filter ........................ FAST-LL`
`Gain ................................ HIGH`
`Amplifier ....................... CLASS AB`
`Balance ........................ Centered`
`Microphone gain ................. 0 dB`

A row opens only the control required to change that setting. Do not make the user enter a generic edit mode to modify values already visible on the page.

Read-only controls such as UAC mode remain visibly read-only rather than looking disabled by accident.

### Routine settings feedback

Routine qualified setting changes apply immediately through the existing verified write/readback path. Preferred grammar:

`Applying…` → `Updated ✓`

The stable state is the value itself, not a permanently displayed success banner. Errors should be local and actionable.

Do not add a global Save/Disregard layer for settings whose device persistence semantics are already verified as immediate.

### Restore defaults

Present **Restore defaults** as one standard DEVICE settings action, not a separate settings subsystem.

The qualified EQ Library Black Pearl preset remains:

- Volume 50%
- FAST-LL
- HIGH gain
- CLASS AB
- centered balance
- microphone gain 0 dB

The confirmation dialog keeps **Also reset EQ to flat** optional and OFF by default. This is EQ Library's restore preset, not a claim about TRN factory defaults.

## EQ editor

EQ editing is intentionally different from routine DEVICE settings because the edits are local/staged until committed.

The editor should make this lifecycle obvious without excessive prose:

1. edit bands/preamp;
2. **Review changes**;
3. review concise change summary;
4. **Apply** or **Discard**.

If there are no valid changes, Review/Apply should not become an ambiguous disabled path. Validation errors must identify the actual field/problem in plain language.

Numeric entry should continue using the user-input normalization layer for verified native gain/Q steps while preserving strict low-level validation.

## My EQs

My EQs should feel like a library the user owns, not an export-status dashboard.

### Root hierarchy

Preferred ordering:

1. Needs attention, only when non-empty
2. Favorites
3. Headphones / IEMs
4. Personal EQs
5. General EQs

Use compact section headers and flatter rows. Avoid a separate card around every item unless a card communicates meaningful grouping/state.

### Managed headphone rows

Primary:

**Manufacturer / Model** or the clearest identity label

Secondary:

- selected-profile count or concise profile summary;
- only genuinely actionable warning/currentness status.

Trailing affordances should be obvious and touch-friendly. Avoid packing several unlabeled glyphs into a small area.

### EQ/profile rows

Use the same general anatomy in My EQs and EQ Library:

- identity first;
- creator/source second;
- compact compatibility/currentness/status;
- one clear primary action;
- overflow/details for secondary actions.

When hardware Flash is available, Flash should live directly on the EQ/profile row/detail rather than navigating through My DAC.

## Needs attention

Treat Needs attention as a compact recovery queue, not a warning dashboard.

Each unresolved app-owned artifact should show only what helps resolve it:

- best available name / file identity;
- why it needs attention in one concise line;
- **Recover** when strict parsing supports recovery;
- **Remove** for exact app-owned artifact deletion;
- malformed/unsupported items remain visible but do not offer fake recovery.

Do not imply that changing Target will fix ownership/recovery identity. Recovery creates a normal device-agnostic Personal EQ when valid.

## EQ Library / Browse

Keep the existing source-agnostic browse hierarchy and verified Manufacturer → Model structure.

Search should remain prominent. Browsing/search results should use the same EQ/profile row anatomy as My EQs where the same concepts appear.

Selection mechanics remain:

- every usable parametric EQ is a checkbox;
- Select all;
- Select none;
- Automatically include new profiles for this headphone;
- preserve explicit exclusions when automatic future inclusion is ON;
- fixed exact selection when OFF.

Do not invent variant/folder meaning to make the hierarchy look prettier.

## Settings

Settings is for durable app behavior, not another copy of live DAC settings.

Keep durable controls such as:

- Automatic / Manual output behavior;
- saved default EQ target;
- export-folder access/state;
- catalog refresh/background behavior where user-facing;
- app update / What's new;
- attribution / about / privacy.

Do not duplicate live Black Pearl DEVICE controls in Settings.

The screen should use standard grouped settings rows with current values visible where applicable.

## Loading, offline, stale, and error states

Keep state messages concise and local.

Preferred patterns:

- **Loading…** only while blocking content cannot yet be shown;
- show cached catalog/library content while refreshing when possible;
- **Offline — showing saved catalog** rather than a full-screen failure when usable cached data exists;
- **Last read** / **Refresh** for stale device state;
- one actionable error plus Retry when a retry is possible.

Avoid showing internal transaction terminology unless it helps solve the problem.

## Feedback grammar

Standardize recurring actions:

| Action | In progress | Success | Failure |
|---|---|---|---|
| DEVICE setting | Applying… | Updated ✓ | Couldn't update — Retry |
| Flash EQ | Flashing… | Applied ✓ | Couldn't apply — Retry |
| Refresh device | Refreshing… | current value/state | Couldn't refresh — Retry |
| Export | Exporting… | Exported ✓ | Couldn't export |
| Catalog refresh | Refreshing… | Updated / No changes | Couldn't refresh — saved catalog remains available |
| Recover EQ | Recovering… | Recovered ✓ | Couldn't recover |

Success states should be transient when the resulting state/value already proves success.

## Layout / density

Use these as defaults, not rigid pixel laws:

- horizontal page margin: ~16 dp phones;
- section spacing: 20–24 dp when changing conceptual groups;
- row internal vertical rhythm: ~8–12 dp;
- minimum interactive target: 48 × 48 dp;
- avoid nested cards and excessive elevation;
- prefer dividers/spacing for lists;
- keep destructive actions visually separated from routine actions.

## Typography

Rely on Material 3 type roles rather than many custom sizes.

Suggested hierarchy:

- screen title: titleLarge / headlineSmall where appropriate;
- main identity: titleMedium / titleLarge;
- row label: bodyLarge / titleSmall;
- secondary metadata: bodyMedium;
- tertiary attribution/status: bodySmall;
- section labels: labelLarge / titleSmall with restrained emphasis.

Do not bold every label. Reserve weight for identity and important current state.

## Icons

Prefer standard Material icons when an icon materially improves scanning:

- Search
- Refresh
- MoreVert
- Favorite
- Edit
- Save/Download only when the action truly means that
- Delete
- Info
- Check / warning where also stated in words

Avoid relying on icons alone for uncommon or destructive actions. Icon-only controls require content descriptions and a minimum 48 dp target.

## Accessibility

Before v0.6 release, validate:

- TalkBack reading order and meaningful labels;
- icon-only controls have content descriptions;
- every state communicated with color is also communicated in text/shape/icon semantics;
- disabled actions have understandable reason nearby where needed;
- 48 dp minimum touch targets;
- dynamic font sizes do not clip key rows/dialog actions;
- selection controls expose selected/not-selected state;
- connection/operation changes are understandable without watching animation;
- dark/light contrast remains adequate under Material theme colors.

## Approved implementation order

1. Remove redundant dashboard/edit-setting shell from My DAC.
2. Finalize DEVICE as grouped `Label … Current value` rows.
3. Make Target explicitly global/action-only.
4. Standardize row/card spacing across My EQs + EQ Library.
5. Convert Needs attention to the compact recovery-list treatment.
6. Standardize feedback grammar.
7. Validate accessibility before release.

Items 1–3 reached the physically reviewed premium checkpoint at `b952aed8d410fe215ac38292d035aec1b16ee2ef` and received an owner-reported PASS on Pixel 9 + TRN Black Pearl. Items 4–7 remain authorized follow-on work.

## Approval boundary

This blueprint is approved. Implementation may continue without another product approval when it stays within the behavior described here. Stop and ask the owner before:

- changing top-level navigation;
- inventing a new hardware control or transaction;
- changing qualified hardware semantics;
- changing My EQs ownership semantics;
- adding new destructive behavior;
- materially changing the approved restore-defaults contract;
- or making another major UX direction change beyond this blueprint.

Release/merge authorization remains separate and explicit.
