# EQ Library v0.6.0 — release notes draft

## What's new

### My DAC

EQ Library can now recognize supported DACs and add a dedicated **My DAC** area for actual connected-hardware state.

When a supported DAC is recognized, navigation becomes:

**My EQs · My DAC · EQ Library · Settings**

My DAC stays available for the current app session after disconnect so the app can clearly distinguish current hardware from **Last read** state instead of making navigation jump.

### One shared DAC connection

A supported DAC now uses one app-wide session shared by **My EQs**, **My DAC**, and **EQ Library**.

After connection or reconnection, EQ Library automatically reads the current EQ and supported DEVICE state. You do not need to reconnect or perform a second read merely because you opened My DAC.

Successful Flash, reset, editor Apply, and DEVICE changes automatically refresh the affected hardware state. Manual **Refresh** remains available for changes made outside EQ Library.

### Automatic EQ targeting

The default behavior is **Automatic (recommended)**. When exactly one supported DAC is present, EQ Library can use that DAC as the effective EQ target without requiring you to preselect it first. With no supported DAC present, the app falls back to your saved **Default EQ target**. If more than one supported DAC is present, EQ Library does not guess.

A persistent **Manual** override remains available in Settings. The setting controls how EQs are prepared, exported, and flashed; it does not change Android's audio output route.

### Read the actual Black Pearl EQ

For TRN Black Pearl, My DAC reads the native hardware EQ and can show:

- current versus Last-read state;
- Flat, exact saved match, modified-known, ambiguous exact, or Unknown identity state;
- active slot and filter count;
- current playback/global-gain context;
- a combined parametric response graph;
- exact native differences when a known saved EQ has been modified through EQ Library.

EQ identity is conservative: cold-start similarity is never treated as source attribution, and ordinary playback volume is not used to invent an EQ match.

### Flash where the EQ already lives

My DAC no longer contains a second **Change EQ** chooser.

- Flash saved EQs from **My EQs**.
- Flash a compatible library EQ directly from **EQ Library** when exactly one supported DAC session is connected.
- Use **My DAC -> EQ** to inspect what is actually on the hardware, edit/capture it, or reset it.

Flash still uses the same deterministic target representation, safety checks, and readback verification underneath.

### Edit EQ on the Black Pearl

The Black Pearl editor starts from a fresh verified hardware read and provides:

- tap-to-select response graph markers;
- exact filter type, frequency, gain, and Q editing;
- All Bands view;
- live deterministic combined-response preview;
- headroom assessment from the complete planned response;
- separate device-limit, caution, and headroom warnings;
- Review before Apply;
- hardware readback verification after Apply.

Dragging the graph never changes hardware. Local edits remain local until explicit Review -> Apply.

### Headroom-aware Apply

EQ Library evaluates the complete planned response rather than simply looking for the largest positive band gain. When additional safe attenuation is needed, the editor makes that requirement visible before a write.

For Black Pearl, EQ Library continues to distinguish its tracked EQ safety adjustment from the DAC's ordinary playback level and preserves the established safe write ordering.

### Save DAC EQ

Unknown or known-modified Black Pearl hardware state can be captured as a local **Personal EQ**.

Captured EQs preserve native filter values and device provenance. You can associate a capture with a real saved/library headphone or intentionally leave it unassociated. EQ Library does not invent a creator/source association, and an exact existing saved match is linked rather than duplicated.

### Reset EQ to flat from My DAC

My DAC includes the qualified Black Pearl **Reset EQ to flat** workflow as a secondary confirmed action. It replaces the hardware EQ with the verified flat state while preserving the established tracked-gain safety behavior rather than arbitrarily resetting listening volume.

A future whole-device **Reset to factory defaults** surface is capability-driven and appears only when an exact DAC's factory/default semantics are independently established. Black Pearl factory-default semantics are not sufficiently established yet, so v0.6 does not guess or expose that action from an observed test baseline or third-party convenience preset.

### A simpler DEVICE screen

Black Pearl DEVICE settings are presented as one concise current-value list instead of a duplicated overview plus editor.

Editable rows are the controls themselves. Routine choices apply through the safe write/readback transaction immediately; settings that may materially change listening level keep a short confirmation. The app does not expose protocol mechanics as normal UI.

Black Pearl ordinary playback is presented simply as **Volume · N%**. The hardware's native raw/dB register remains an internal transaction detail rather than a user-visible baseline. After a verified Apply, fresh readback becomes the new current volume; there is no persistent user-facing delta from the value that happened to be present when the screen opened.

DEVICE changes use a common progress pattern across supported DACs: **Applying <setting>…**, then a brief verified **<Setting> updated ✓**, or a truthful error/current-state message. The app no longer labels the retained pre-write snapshot `Last read` while a normal write is actively being verified.

The current Black Pearl surface includes established state for volume, DAC reconstruction filter, gain mode, amplifier topology, balance, microphone gain, firmware, and USB audio mode according to the capability/qualification policy for the exact device.

### Black Pearl USB audio mode

EQ Library detects the active **UAC 1.0** or **UAC 2.0** mode from the current USB AudioControl descriptors. There is no speculative in-app UAC switch.

The DEVICE screen includes the concise manual startup sequence:

- UAC 1.0: disconnect the Black Pearl, leave headphones connected, hold **+** and **−**, reconnect USB, then release after power/enumeration;
- UAC 2.0: reconnect normally without holding the buttons;
- EQ Library automatically reads the replacement session and displays the detected mode.

### FiiO JA11 foundation

v0.6 also builds the shared My DAC/session framework for the FiiO/JadeAudio JA11. Software-established device state and controls use the same capability-driven architecture, and EQ selection/Flash belongs to My EQs / EQ Library rather than a duplicate My DAC chooser.

JA11 uses the same shared DEVICE progress/current/stale presentation while retaining its own independently established native `0..60` volume scale. Device-specific units and reset semantics are never borrowed from Black Pearl.

JA11 remains **Hardware validation pending** until the exact physical checklist can be run on the device.

## Safety and privacy

- No account, analytics, telemetry, or cloud backend is added.
- My DAC state stays local.
- Reconnect never pushes cached values back to hardware.
- Requested editor or DEVICE state is not reported as current until verified hardware readback succeeds.
- Normal DEVICE writes are not silently retried after transfer.
- Firmware/bootloader/cross-flash writes, raw register consoles, and USB-identity mutation are not exposed.
- Unsupported controls disappear rather than being guessed from a similar device.
- Factory/default values are not inferred from another DAC, another firmware, an observed test baseline, or a third-party button label.
