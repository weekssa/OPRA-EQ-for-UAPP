## Current product decision

The exact qualified SIMGOT EW300 DSP is implemented as another DAC inside the existing shared My DAC architecture. The shipping capability boundary is deliberately narrower than generic KT02H20-family tooling and narrower than Black Pearl's control inventory.

Supported and implemented for the exact qualified profile:

- exact identity/session recognition and freshness;
- five-band direct-Hz **Peak** EQ readback;
- shared response graph with active-band markers, 0 dB reference, and accessibility description;
- truthful Flat / deterministic exact saved match / ambiguous exact match / Unknown state presentation;
- local five-band Peak editing and Review → Apply;
- guarded Flash from the existing My EQs / EQ Library hardware-output flow;
- Peak-only Personal EQ capture;
- Reset EQ to flat;
- authoritative-session manual Refresh for EQ and DEVICE;
- reconnect/final-readback status and privacy-safe operation evidence;
- read-only playback/global-gain device state; and
- source low/high-shelf adaptation to an **Optimized** five-Peak derived representation only when fixed response-error/safety gates pass.

Playback/global gain is device state outside captured EQ identity. The evidence does not establish a safe independent EW300 volume UX, so no volume slider/write is exposed. DAC filter, gain mode/PGA, amplifier/output topology, balance, microphone gain/control, UAC switching, firmware/update, routing/headset configuration, and factory-device defaults remain **INSUFFICIENT_EVIDENCE**. Firmware/bootloader/erase/calibration/recovery/cross-flash work remains unsafe/out of scope. VID/PID-only or unknown revisions are not authorized.

## Shelf-source closure

The historical shelf problem came from the older finite-hardware adapter requiring source filter families to be natively supported. The current representation-v3 path separates source-response compatibility from target-native controls:

1. canonical low/high shelves remain unchanged;
2. the complete source response is evaluated;
3. the EW300 target adapter derives quantized Peak candidates;
4. no more than five Peak bands are selected/refined deterministically;
5. fixed RMS and maximum-error gates decide whether the result is `Optimized` or `Not suitable`; and
6. unsupported filter families fail explicitly rather than being silently dropped.

The regression corpus covers representative OPRA, AutoEQ, community/general, strict import, Personal EQ, captured-DAC, over-budget, determinism, immutability, and Not-Suitable paths. Android CI #1736 passed the corrected corpus together with unit tests, lint, debug/release assembly, and connected emulator tests on the corresponding code plus privacy-safe orchestration documentation. No additional optimizer rewrite was justified by the corpus.
