## New owner-reported audio-channel investigation

On 2026-09-24 the owner reported that the exact EW300 path plays only through the right earbud and
that the left side crackles at high level, while the same IEMs work with another DAC. This is a
high-priority diagnostic issue, not evidence that the app caused the defect. The durable
investigation and bounded next steps are recorded in
`docs/V0.7_EW300_AUDIO_CHANNEL_INVESTIGATION.md`.

The initial source audit found that EQ Library claims only the EW300 HID PEQ interface and contains
no PCM, channel-routing, stereo/mono, or left/right-balance implementation. The EW300 descriptor
evidence separately identifies UAC stereo playback interfaces. The audit is therefore keeping the
app protocol, Android/UAPP audio route, EW300 UAC/analog path, and cable/earpiece path distinct.
The live installed candidate was previously traced to `main` source `a8abf78275554b44bf2f6a3b0042dfcd8fe8441c`,
matching the owner's installed candidate URL. PR #31 corrected the stereo-gain write defect and
PR #32 added the guarded output-gain control; both are now represented in the merged exact signed-main
candidate. The owner subsequently confirmed balanced stereo audio, normal safe-volume behavior,
successful output-gain adjustment, and successful EW300 Flash/readback testing on the final candidate.
No separate balance or routing control is claimed.

The owner then reproduced the same right-only/left-crackle symptom with the EW300 DSP cable on a
computer, while the alternate cable/DAC worked. This strongly excludes an Android-only, UAPP-only,
or runtime EQ Library audio-routing defect. Review of the preserved stock and failed-operation raw

stereo digital-gain register `0x66`, leaving byte 1 unchanged. PR #31 now reads the protocol layout,
writes both stereo gain bytes, fails closed for unequal stereo readback, and records stable R8-safe
operation outcomes. The owner-reported final signed-candidate PASS closes this investigation for
the exact qualified EW300 identity; it does not establish support for unknown EW300 revisions or
add a user balance/routing control.

## Current product decision

The exact qualified SIMGOT EW300 DSP is implemented as another DAC inside the existing shared My DAC architecture. The shipping capability boundary is deliberately narrower than generic KT02H20-family tooling and narrower than Black Pearl's control inventory.

Supported and implemented for the exact qualified profile:

- exact identity/session recognition and freshness;
- five-band direct-Hz **Peak** EQ readback;
- shared response graph with active-band markers, 0 dB reference, and accessibility description;
- truthful Flat / deterministic exact saved match / ambiguous exact match / Unknown state presentation;
- local five-band Peak editing and Review → Apply;
- guarded Flash from the existing My EQs / EQ Library hardware-output flow;
- Peak-only Personal EQ capture;
- Reset EQ to flat;
- authoritative-session manual Refresh for EQ and DEVICE;
- reconnect/final-readback status and privacy-safe operation evidence;
- read-only playback/global-gain device state; and
- source low/high-shelf adaptation to an **Optimized** five-Peak derived representation only when fixed response-error/safety gates pass.

Playback/global gain remains outside captured EQ identity. The exact qualified EW300 fingerprint now
has a physically confirmed output-gain row: `-64.0..0.0 dB` in 0.5 dB steps, both stereo bytes,
one Save, and final readback. The user baseline is separate from EQ-applied headroom. DAC filter,
gain mode/PGA, amplifier/output topology, balance, microphone gain/control, UAC switching,
firmware/update, routing/headset configuration, and factory-device defaults remain
**INSUFFICIENT_EVIDENCE**. Firmware/bootloader/erase/calibration/recovery/cross-flash work remains
unsafe/out of scope. VID/PID-only or unknown revisions are not authorized.

## Shelf-source closure

The historical shelf problem came from the older finite-hardware adapter requiring source filter families to be natively supported. The current representation-v3 path separates source-response compatibility from target-native controls:

1. canonical low/high shelves remain unchanged;
2. the complete source response is evaluated;
3. the EW300 target adapter derives quantized Peak candidates;
4. no more than five Peak bands are selected/refined deterministically;
5. fixed RMS and maximum-error gates decide whether the result is `Optimized` or `Not suitable`; and
6. unsupported filter families fail explicitly rather than being silently dropped.

The regression corpus covers representative OPRA, AutoEQ, community/general, strict import, Personal EQ, captured-DAC, over-budget, determinism, immutability, and Not-Suitable paths. Android CI #1736 passed the corrected corpus together with unit tests, lint, debug/release assembly, and connected emulator tests on the corresponding code plus privacy-safe orchestration documentation. No additional optimizer rewrite was justified by the corpus.
