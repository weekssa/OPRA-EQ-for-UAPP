Inspection of the downloaded APK (SHA-256 `669b4c7a831c0edd8888dde657a6776742edb8530a3921ffab73aa50c8bf66c4`) confirms no definition of `com.weekssa.opraeqforuapp.diagnostics.Ew300UsbDiscoveryActivity` in any DEX file. The manifest names that missing class as launcher. This is a sufficient launch-failure cause; no phone stack trace was available.

The custom build registered `src/debug/java` as extra Java sources only. AGP 9 built-in Kotlin requires the Kotlin source set. Earlier exception handling around receiver registration could not fix code that was absent from the artifact. The former unit/lint/build/signing passes did not test launchability.

The class-definition gate has been tested against the failing owner APK and correctly rejects it. Candidate workflow evidence must pass before another owner handoff. This does not establish any device protocol or physical capability.
