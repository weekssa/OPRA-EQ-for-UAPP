## Diagnostic launch failure

Owner reported that signed diagnostic `c0083459edbcec095d420b22aa8b65a32ccafa84` installs but immediately stops. Inspection of the downloaded APK (SHA-256 `669b4c7a831c0edd8888dde657a6776742edb8530a3921ffab73aa50c8bf66c4`) confirms no definition of `com.weekssa.opraeqforuapp.diagnostics.Ew300UsbDiscoveryActivity` in any DEX file. The manifest names that missing class as launcher. This is a sufficient launch-failure cause; no phone stack trace was available.

The custom build registered `src/debug/java` as extra Java sources only. AGP 9 built-in Kotlin requires the Kotlin source set. Earlier exception handling around receiver registration could not fix code that was absent from the artifact. The former unit/lint/build/signing passes did not test launchability.

Correction: register the directory as Kotlin sources; require a DEX class-definition check and two actual cold launches of the signed APK on Android 36. The class-definition gate has been tested against the failing owner APK and correctly rejects it. Candidate workflow evidence must pass before another owner handoff. This does not establish any device protocol or physical capability.

The workflow packages the exact source commit, APK checksum, signer/alignment reports, class-definition report, launch output and rendered UI XML with the signed diagnostic. A failed launch prevents candidate upload. Results are attached to the exact workflow run, not generalized to future builds.
