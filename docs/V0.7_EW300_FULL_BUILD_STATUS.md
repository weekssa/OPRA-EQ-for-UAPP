## Owner session stop: no-write Apply preflight

The owner used the exact signed candidate and exported both operation reports. The report proves
that the exact identity and baseline were captured, but `registerWriteCount=0`,
`saveCommandCount=0`, `permissionRequestCount=0`, `mutationReplayCount=0`, and
`stateKnown=true`. The operation stopped before mutation with the UI message that the reviewed
EW300 global gain was unavailable or outside the qualified range. Source inspection identified the
cause: the editor read `dedicatedEqPreampDb`, while EW300’s verified `0x66` value is represented as
`playbackGainDb` and must be treated as an absolute device-global-gain headroom mechanism.

The current branch corrects that mapping and adds regression coverage. Do not retry the old APK;
the replacement signed candidate must pass targeted tests, complete CI, signing, installation,
launch, and release-polish checks before any further hardware action.

## USB permission-flow follow-up

The first owner attempt to use the newly enabled EW300 Flash path did not produce a verified Flash
result. Android showed both the normal USB permission prompt and a system app chooser for `USB
Audio Player PRO` versus `EQ Library` while the EW300 was reconnecting. The owner was told to stop
and not retry the mutation. This is not hardware PASS evidence and is not counted as a Flash result.

The app previously advertised a manifest-wide `USB_DEVICE_ATTACHED` handler in addition to its
exact in-app USB session. That declaration can make Android treat EQ Library as a competing USB
handler and relaunch it during a brief EW300 re-enumeration. The follow-up removes only that
automatic system-handler declaration. The app still uses its exact manufacturer/product/HID
identity checks, the in-app USB permission request, and the existing dynamic attach/detach
reconnect handling. No device authorization, protocol command, or retry policy is broadened.

The current replacement candidate above passed the complete software, security, signing,
installation, and cold-launch gates. Its one guided owner session is now closed; the old
`8bb87aa` APK must not be used again for Apply, and Save qualification must not be run again.

## Intentionally unsupported

This build does not authorize volume, headset, UAC, microphone, other Black Pearl controls,
firmware, bootloader, erase, calibration, recovery, cross-flash, unknown EW300 revisions, or
compatibility claims based only on a chip family or VID/PID. “Fully functional” means only the
exact EW300 Peak EQ feature set verified for the qualified fingerprint and signed candidate.
