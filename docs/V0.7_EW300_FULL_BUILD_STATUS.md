## 2. Qualified EW300 product capability

The shipping EW300 native path is five direct-Hz **Peak** bands. The product supports readback, local edit/review, guarded Apply, guarded Flash through the existing hardware-output flow, Peak-only Personal EQ capture, Reset EQ to flat, reconnect-aware final readback, and manual EQ/DEVICE Refresh through the authoritative session.

The My DAC overview now uses the shared response graph and provides truthful Flat / exact saved match / ambiguous exact match / Unknown presentation. Exact attribution is based on complete native representation, not acoustic/curve similarity. Stale state remains explicitly “Last read”; failed reads are not silently presented as current.

The DEVICE tab is intentionally compact. It reports verified playback/global gain, active Peak-band count, connection freshness, and Refresh. Diagnostic capability-report and restoration controls are not enabled in the signed product candidate. Playback/global gain remains device state outside captured EQ identity.

Independent capability research did not establish a safe standalone EW300 volume contract or any additional DEVICE write. DAC filter, gain mode/PGA, amplifier/output topology, balance, microphone gain/control, UAC switching, firmware/update, routing/headset configuration, and factory-device defaults remain **INSUFFICIENT_EVIDENCE**. Firmware/bootloader/erase/calibration/recovery/cross-flash remain unsafe/out of scope.

## 5. Shelf-source root cause and regression closure

The historical shelf issue was in target adaptation, not canonical parsing: the older finite-hardware flow required source filter families to be natively supported by the target. That is too restrictive for a Peak-only device that can safely approximate a shelf response.

Representation v3 now:

1. preserves canonical source shelves unchanged;
2. permits low/high shelves as **source response** inputs for the EW300 adapter without claiming native shelf support;
3. generates quantized Peak-only fit seeds;
4. evaluates the complete source response over the fixed logarithmic grid;
5. selects/refines at most five Peak bands deterministically;
6. retains source preamp when representable or derives conservative target-side headroom when absent;
7. enforces fixed RMS and maximum-error limits; and
8. returns `Not suitable` for unsupported/unreliable cases rather than truncating or silently altering the source.

The cross-source corpus covers representative current OPRA shelf data, AutoEQ, community/general, strict imported PEQ text, Personal EQ, captured-DAC shelves, mixed/over-budget cases, deterministic output, canonical immutability, and explicit unsupported-filter failure.

A test-only Truth assertion compatibility error in the first corpus commit was corrected without weakening assertions. Android CI #1736 then passed unit tests, lint, debug/release assembly, and connected emulator tests on the same runtime/test code plus documentation cleanup. The corpus did not demonstrate a new optimizer defect, so no additional production algorithm churn was introduced.
