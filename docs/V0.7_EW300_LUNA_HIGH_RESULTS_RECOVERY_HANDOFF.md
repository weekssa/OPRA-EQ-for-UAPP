## 9. Phase B — implement one authoritative USB operation state machine

Flash, Apply, Reset, initial connection, and post-Save recovery must use the same authoritative EW300 session owner. UI and navigation must never open an independent session.

### Required operation stages

```text
IDLE
→ AUTHORIZED_SESSION
→ BASELINE_CAPTURED
→ WRITING
→ VOLATILE_VERIFIED
→ SAVE_SENT_ONCE
→ SAME_SESSION_READBACK or WAITING_FOR_REPLACEMENT
→ REPLACEMENT_IDENTITY_VERIFIED
→ REPLACEMENT_AUTHORIZED
→ FINAL_READBACK
→ VERIFIED
```

Any unexpected transition becomes a terminal failure or `STATE_UNCERTAIN`, according to whether the app can prove the hardware remains at the baseline.

### Permission rules

1. At Flash/Apply/Reset start, reuse the currently open, already authorized exact session.
2. If the current session has permission, the operation must make **zero** permission requests before the first mutation.
3. Do not close or recreate the active connection merely because Flash was confirmed.
4. A new permission request is allowed only after:
   - Save was sent exactly once;
   - an actual detach or replacement device instance was observed;
   - the old session was invalidated;
   - the operation is explicitly waiting for replacement readback; and
   - the replacement passes the full supported EW300 identity/profile check.
5. If Android already grants the replacement instance permission, reopen it without prompting.
6. If permission is required for the proven replacement instance, show plain language explaining that the EW300 restarted after saving and Android needs access again.
7. After replacement permission, resume with **readback only**. Never resend filters, gain, or Save.
8. Permission denial ends the operation truthfully. It must not retry or start a competing connection.
9. Duplicate permission, attach, detach, or lifecycle callbacks must be idempotent and generation-correlated.
10. A different or insufficiently identified USB device cannot resume the transaction.

### Mutation rules

- Capture the complete readable baseline before the first write.
- Validate exact four-byte responses.
- Preserve safe gain/filter ordering.
- Verify volatile state before Save.
- Send Save at most once.
- Never automatically retry a write or Save.
- Revalidate the full state before reporting success.
- Before Save, restore and verify the baseline when safely possible.
- After an ambiguous write, Save, detach, callback, or restoration, stop as `STATE_UNCERTAIN` and require a fresh complete read before any later mutation.
- Persist only the minimum operation journal needed to prevent process recreation from resending a mutation.

**Exit gate:** The state machine makes an immediate pre-write permission request impossible for an already authorized active session and makes post-Save replacement permission safe and readback-only.
