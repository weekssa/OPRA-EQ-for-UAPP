## Public research boundary

Research found no authoritative public EW300 protocol specification. The
SIMGOT manual establishes the integrated USB-C DAC/DSP product but not its PEQ
wire protocol. DevicePEQ and KT Micro tooling document related generic five-band
patterns and are treated as reference-only hypotheses; their behavior is not
adopted without exact-device evidence. The relevant sources and license notes
are recorded in `docs/EW300_DSP_PROTOCOL_NOTES.md`.

## Software gate record

The repository has no checked-in Gradle wrapper and the local environment has no
system Gradle executable. Gradle validation therefore runs through the
repository's GitHub-hosted workflow (`gradle 9.4.1`) after the replacement branch
is pushed. Local checks still include source/reference audits, `git diff --check`,
deterministic fixture inspection, and documentation consistency. A signed APK,
package/signer/checksum, and launchability are release gates, not inferred from
unit-test success.

The candidate adds an Android-free `Ew300CapabilityBatch` with strict read-only
preflight/reporting. Mutating capability cases are declarative but skipped unless
an exact signed diagnostic plan explicitly enables them; the default utility never
probes persistence or undocumented commands.

## Hardware budget decision

No new discovery installation is justified by the current evidence. At most one
bounded capability-resolution session may be requested if a necessary user-visible
feature cannot be decided from the evidence ledger. The consolidated owner
validation session remains blocked until the complete signed beta passes all
software gates. Merge and release remain explicitly unauthorized.
