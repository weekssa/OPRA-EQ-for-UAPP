## Purpose and qualification boundary

C05-C is one read-only Black Pearl production identity/session/read/navigation qualification. “Read-only” means no DAC setting-changing UI/API path is invoked. Production READs transmit outbound request reports and the transport may automatically reissue one nondestructive timed-out request once. Do not claim zero USB reports, zero retries, or raw bit-for-bit equality. Compare the same displayed fields at UI precision. No restoration write is expected or allowed because the procedure changes no settings.

Use three phases:

- **Phase A — complete off-phone preflight.** Finish exact candidate/APK, live PR/check/base/release state, source/UI action audit, plan, tooling, ignored evidence paths, commands, abort/release procedure, and independent review. No Pixel query or occupancy timer.
- **Phase B — wireless ADB target binding.** A read-only host/Android transport task, not a DAC session. The owner may use the Pixel normally. Discover current ADB services, uniquely bind the Pixel by stable identity, verify the installed APK, app-process readiness, and capture command paths, and persist a sanitized binding. Do not operate the app UI or query/control the DAC in this phase.
- **Phase C — active DAC physical qualification.** Begins only after the synchronized exact-state review for this plan/candidate passes and the fresh Phase B binding made after that review passes. That one review is the sole independent entry authorization and evaluates G3 for this exact plan. The Black Pearl may already be attached; never change the cable. Use the fresh bound wireless ADB target. C1 performs one prepared, read-only installed base APK recheck before any Black Pearl descriptor observation; do not perform GitHub, candidate, SDK-tool, or other package/APK discovery during active DAC work.

Time is an optimization metric only. Target active Pixel/DAC time is 5–10 minutes. Elapsed time alone never fails, consumes, or aborts a session. Stop only for an actual safety/procedure condition: wrong or ambiguous Android identity; absent/mismatched DAC; unknown/unsafe state; unexpected mutation; required read unavailable; unrecoverable ADB failure during required evidence; procedure no longer matches production behavior; or an owner request to stop. If a nondestructive READ is active, do not disconnect or kill it; allow it to settle safely before release.

No Reset, Apply, Flash, Save, DEVICE setter, fault injection, cable change, forced process kill, manual replay of uncertain I/O, or disconnect during activity. Human-heard TalkBack, headphones, JA11, and EW300 are excluded from this beta gate.

The resolver never pairs, installs, launches, changes settings, or uses a USB ADB transport. It distinguishes `_adb-tls-connect._tcp` from `_adb-tls-pairing._tcp`, ignores pairing-only advertisements, validates current IPv4 or bracketed IPv6 endpoints and port range, and inspects current device rows. If service names lack the expected Pixel serial and no Pixel has yet been identified, it may connect to current advertised TLS-connect endpoints and query Android identity properties read-only; this is the owner-required ambiguity fallback, not endpoint guessing. It never queries an unmapped remembered host:port or a pairing endpoint. Exact serial/model/product/API/build properties select the Pixel; multiple endpoints reporting that same identity are collapsed only if they share one current boot ID (or are the same endpoint). Newly opened non-Pixel routes are detached; a detach failure blocks readiness. Conflicting or indistinguishable multiple target identities fail closed.
