## 6. Current Model D identity model

### Product rule and implemented behavior

A serial is optional continuity evidence, never a JA11 support or read/write prerequisite. Initial
sessions require exact supported VID/PID, exactly one plausible JA11 candidate, a valid uniquely
selected HID interface with one eligible interrupt IN and OUT endpoint, current permission, fresh
open/claim, and a current session generation. The same unique-candidate gate applies to JA11
reacquisition; shared non-JA11 selection behavior is unchanged.

Expected-reset verification binds the requested control/value and transaction token to the original
session, accepted write outcome, generation, detach generation, and watchdog/permission owner. It
requires the accepted write, expected detach and old-session invalidation, exactly one supported
replacement, current permission, fresh open/claim, a new generation, and authoritative fresh
readback. Compare serials only when both sessions expose usable serials and reject mismatch. Missing
serial is allowed only when every operation-continuity gate passes. The result means state verified
on the sole returning supported JA11; it does not prove the same physical unit returned. Uncertain
writes are never replayed. Unsolicited reconnect without a pending operation starts a fresh session
and baseline.

Android’s [public USB API](https://developer.android.com/reference/android/hardware/usb/UsbDeviceConnection#getSerial()) exposes a serial getter on the opened connection; AOSP implements it through the USB serial string descriptor and can return null when it obtains no string ([framework JNI](https://android.googlesource.com/platform/frameworks/base/+/7647091436c45af2d82f12c9ea9ec77fa309b49b/core/jni/android_hardware_UsbDeviceConnection.cpp#197), [USB host serial lookup](https://android.googlesource.com/platform/system/core/+/ec9e7b1/libusbhost/usbhost.c#421)). J024 does not distinguish an absent descriptor from an unsuccessful descriptor-string read. This API behavior is separate from JA11 firmware behavior and separate from the project’s stricter authorization policy.

- **UNKNOWN:** whether this JA11 has a nonzero `iSerialNumber` descriptor index, whether a null string reflects an absent descriptor or failed read, and whether another JA11 could share a reported serial. Without serial, same-unit continuity remains unproven by design.

## 7. Current JA11 session and I/O gate

Model D requires exactly one supported JA11 whenever the app opens, reads, writes, or verifies a
session. The transport now rechecks candidate count as part of `isCurrentSession()`, at the HID
write boundary, before/during input drain, before the HID read request, and during response polling.
The JA11 control repository and `DacSessionRepository` also reject ordinary snapshots and writes
when the current candidate count is not one. A zero-candidate control result is disconnected; two
or more candidates are ambiguous. Other shared transports keep their existing selection policy.

A read or write remains pinned to the connection and generation captured by its caller. Cardinality
checks reject the operation if another supported JA11 becomes observable in the current candidate
set or through a processed Android attach/detach event; they never retarget I/O to that unit. Android
cannot distinguish a same-path/PID serialless replacement with the same HID shape before its
attach/detach callback is delivered, so the app cannot claim same-unit continuity in that interval.
If cardinality changes after a write was sent, the result cannot be reported as verified. Restart
verification still separately requires an accepted write, observed expected detach, invalidated old
session, one fresh permissioned replacement, successful open/claim, a new generation, optional serial
match when both are available, and authoritative fresh readback. An uncertain write is not replayed.
