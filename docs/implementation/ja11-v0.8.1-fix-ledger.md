## Current milestone

**M0 — bootstrap and evidence reconciliation COMPLETE. M1 — regression correction and local
verification COMPLETE.** Independent review confirmed the false-verification and Flash/Reset/editor
read-pinning races are closed. The JA11 restart-write result is now distinct from pre-send stale and
incomplete/unknown outcomes; restart-capable controls are registered before the report, wait for a
matching physical identity, and use read-only verification after re-enumeration. Terminal pending
states clear busy status. HID session generation and detach generation are checked under the report
mutex. Flash, Reset, and editor transactions pin the starting physical session and stop without
continuing or saving after it changes. The separate `ja11Diagnostic` build type uses the same
production implementation with diagnostics gated off in normal variants.

**G5 preparation:** the existing snapshot reader obtains all five stored User 1 bands and global EQ
gain when the program is Off or User 1, although the normal UI correctly hides inactive coefficients while Off. The reader intentionally does not emit a complete baseline for built-in Vocal/Classic/Bass programs.
The current patch adds a diagnostic-build-only `SNAPSHOT_READ_COMPLETE` log record with the source
SHA, generation, active program, global gain, and all five native band values. An independent reviewer
confirmed the record is emitted only after a complete read, is absent from normal builds, and does not
change any read/write decision. This makes it possible to build a temporary, baseline-identical
Personal EQ payload after the exact hardware read without asking the owner to interpret or transcribe
protocol data. The payload will be imported through existing My EQs UI in the diagnostic package
sandbox, checked against the captured values, and used for the single Flash from Off. It is a test
backup, not a claimed device-capture provenance record and not a stable-app library change.
