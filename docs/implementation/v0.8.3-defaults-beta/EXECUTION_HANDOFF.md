## 4. Mechanism and safety contract

Existing research found UAC sends 0x20 and mic sends 0x12, without a separate app-visible generic commit. EQ Save is 0x19(program); there is no established independent gentle-save packet. A shared internal firmware commit is an inference. Do not implement an invented opcode, same-value persistence or presumed EQ staging requirement.

Perform a bounded review of the existing evidence for an independently supported settings-only mechanism, then proceed with the owner-selected **mic round trip** if none is established. Do not let open-ended firmware research delay the agreed implementation or silently substitute a new unqualified mechanism. Record any promising alternative for separate review. No firmware installation, opcode probing or speculative protocol fixes.

Default transaction, ViewModel-owned under one shared JA11 operation gate:

1. Obtain fresh coherent baseline/session/identity, volume, active program, original mic state, UAC/PID, firmware and applicable EQ evidence.
2. Write the target setting zero times if unchanged, otherwise once; verify runtime target and companion state.
3. Write mic once to the opposite original state. Handle the established expected detach, permission and verified replacement session; verify actual state before proceeding.
4. Write mic once back to its original state, then handle/verify the second replacement session.
5. Verify target and companion settings, original mic restoration, unchanged UAC/PID/firmware and applicable EQ state. Publish fresh DEVICE/EQ presentation without selecting User 1 just to draw/read a graph.

Original On means On→Off→On; original Off means Off→On→Off. Successful default operations have exactly two mic writes and zero or one target write. No 0x19 Save, 0x20 UAC write, band/gain write, EQ Apply 0x18, helper program selection or explicit extra reset. Use existing framing/codecs. Ordinary mic/UAC controls and qualified Flash/editor/Reset retain their established behavior.

One operation owner/gate covers both reconnects and permission waits. Reuse existing unlocked primitives; avoid deadlocking by nesting public gate-taking calls. Keep busy state throughout, block competing mutations and prevent navigation from cancelling operation completion. Respect current session/identity fences; do not push cached settings on reconnect.

Do not replay a target or mic write, automatically switch to another persistence mechanism, or continue mutations after an uncertain/failed phase. Bounded established read-only late-detach recovery is allowed. Failure can leave the target applied or mic temporary/unknown; display the last verified actual state and distinguish runtime success from unconfirmed default saving. Do not blindly roll back or promise restoration after every interruption.
