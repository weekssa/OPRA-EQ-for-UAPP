## Build-tool dependency advisory assessment

Current main reports 51 open transitive Maven alerts (3 critical, 20 high, 26 medium, 2 low) surfaced through `settings.gradle.kts`. The default-branch SBOM maps the alerted libraries to Android build, Gradle, emulator, or test components. None of the flagged coordinates appear in the v0.7.2 app `releaseRuntimeClasspath`; a mapped minified candidate DEX scan found zero flagged package-class matches. This is not evidence of zero build-environment risk. No broad dependency upgrade was included because it is outside the stabilization scope; track critical/high build-tool remediation separately.

Counts, failures, errors, skips, lint diagnostics, run URLs, artifact IDs, checksums, signers, emulator identities, and unavailable gates must be recorded in the corresponding row or `ARTIFACTS.md`. Emulator evidence counts only when captured command output proves that the named device ran the test.

The pristine v0.7.1 API 26 failure was reproduced on a freshly wiped AVD with `dalvik.vm.heapgrowthlimit=48m`. `CanonicalCatalogRepository.loadSnapshot()` first buffered the 19,375,344-byte canonical catalog as a `String`. Streaming fixed that allocation, but an early three-second smoke falsely passed; longer cold launches exposed additional pressure from eager lookup indexes, profile alias resolution, band normalization, and acoustic deduplication. The current implementation uses lazy catalog indexes and band projections, compact collision-checked acoustic fingerprints, fixed-precision formatting with exact fallback checks, and background catalog projection. One exact-commit attempt logged an OOM while UIAutomation dumps collided; the serialized clean rerun passed. Exact PR head `e7f2fc93` also passed the API 26 x86_64 CI smoke. Signed-candidate and promotion install/upgrade gates passed on exact release source `b8e90b9b`.
