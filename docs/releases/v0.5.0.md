# EQ Library v0.5.0

v0.5.0 is the largest output-system update so far. It expands EQ Library from a small set of output paths into a unified, source-agnostic output framework, improves finite-hardware adaptation, and prepares the app for additional DACs and import targets without changing the canonical EQ source.

## What’s new

### More output choices

Selectable outputs are now grouped as **Hardware DACs**, **Apps**, and **Universal formats**.

New and expanded output paths include:

- **TOPPING Tune** — standard AutoEq-style parametric `.txt` import with a 10-band target.
- **EasyEffects** — Equalizer APO-style parametric text, up to the declared target limit.
- **Equalizer APO** — parametric configuration text.
- **AutoEq / Equalizer APO Parametric** — portable universal parametric text.
- **AutoEq GraphicEQ** — portable 127-point GraphicEQ text.
- Existing **USB Audio Player PRO / ToneBoosters**, **Poweramp / Poweramp Equalizer**, and **Wavelet** paths remain available.

The active output remains an operating context only. Switching outputs changes My EQs membership, conversion/fidelity, export behavior, and hardware controls without hiding valid canonical EQs from the library.

### Better finite-hardware EQ adaptation

TRN Black Pearl, FiiO JA11, and stock-firmware JCALLY JM12 now use one deterministic finite-hardware response adapter.

For supported source filters, EQ Library now:

1. preserves an exactly representable source as **Exact**;
2. preserves the same filter structure when only native target rounding is required and reports it as **Optimized**;
3. otherwise fits the **complete source response** to the target band budget and requires fixed response-error gates;
4. rejects a profile as **Not suitable** when a safe/faithful target representation cannot be produced.

This replaces the old first-N approach for finite hardware. Canonical source bands and metadata remain unchanged. The independent UAPP/ToneBoosters contract still uses its established first-10 source-priority behavior because that is a separate format requirement.

### TRN Black Pearl improvements

Black Pearl file export and Direct Flash now consume the same shared 10-band device representation.

- Profiles over 10 bands are adapted from the complete source response instead of simply taking the first 10 bands.
- Native rounding, full-response fitting, and generated playback headroom are reported distinctly from true Exact preservation.
- Flash confirmation uses the same final plan that the transaction writes, so displayed fidelity, gain, and warnings cannot disagree with the device write.
- Ordinary Optimized adaptation no longer triggers **Flash anyway**. That wording is reserved for an actual hardware caution, such as a protocol-encodable filter gain outside the currently validated listening range.
- Black Pearl `.txt` export uses the verified pyBlackPearl `PK / LS / HS` shelf/peak syntax and preserves the true derived preamp. If a third-party importer has a narrower convenience range, EQ Library reports that limitation instead of silently clamping the preset.
- **Reset EQ to flat** from v0.4 remains available with its qualified fail-safe gain-restoration behavior.

### TOPPING Tune

TOPPING Tune is now a selectable **Apps** output using standard AutoEq-style parametric text and a 10-band target.

EQ Library uses complete-response fitting when a source cannot fit the 10-band target directly and does not silently clamp an out-of-range source preamp. Because TOPPING’s public documentation does not establish the downstream hardware storage quantization after import, v0.5 conservatively reports TOPPING Tune output as **Optimized** rather than claiming unproven Exact downstream fidelity.

### FiiO JA11 and JCALLY JM12

v0.5 includes implemented Direct Flash paths for:

- **FiiO JA11** on normal FiiO firmware — five-band hardware PEQ, global EQ gain, Apply/Save/readback flow, and Reset EQ to flat.
- **JCALLY JM12** on stock firmware — five-band hardware PEQ, readback verification, tracked EQ Library playback-gain adjustment, and Reset EQ to flat.

Both Direct Flash toggles are **OFF by default**, and Add/Save never automatically writes hardware.

**Hardware status for v0.5.0:** both JA11 and JM12 remain **Hardware validation pending** because the physical test units are not yet available. Their hands-on qualification is intentionally deferred to the next incremental release and is **not a v0.5.0 publication blocker**. Do not interpret their inclusion as a hardware-qualified claim. Stock JM12 power-cycle persistence is also not claimed.

No firmware update, bootloader, cross-flash, cloud/share-code, or unrelated DAC-control functionality is included. No unverified preset-file format is invented for JA11 or JM12.

## Android architecture and reliability

v0.5 also completes an internal MAD-style architecture refactor intended to make the app easier to maintain without changing DSP/conversion/device behavior.

- `MainActivity` is the lifecycle/platform boundary.
- `EqLibraryViewModel` owns immutable screen state.
- A manual composition root constructs platform-backed dependencies.
- Repositories use narrower injected contracts instead of retaining Activity/Context responsibilities.
- USB hardware sessions survive ordinary configuration changes until the ViewModel is actually cleared.
- Transient selections and pending export UI state expected to survive Activity recreation use saveable state.
- SAF ownership lookup now distinguishes a genuinely missing exported document from a temporary provider/permission lookup failure, preventing transient access errors from being mistaken for deletion.

## Hardware qualification status

**TRN Black Pearl — qualified for v0.5.** The destructive/fidelity/persistence regression passed on Pixel 9, including connection, Cancel/no-write, Exact Flash, Optimized complete-response Flash, full power-cycle persistence, Reset-to-flat persistence, and the explicit out-of-validated-range caution path. The later MAD architecture refactor preserves device/DSP/conversion behavior, so that completed qualification remains valid through the documentation-only release closeout.

**FiiO JA11 — Hardware validation pending.** Physical qualification is deferred to the next incremental release when the device is available.

**JCALLY JM12 — Hardware validation pending.** Physical qualification is deferred to the next incremental release when the stock-firmware device is available. Power-cycle persistence remains unclaimed until it is physically established.

## Install / upgrade

The public release asset will be `EQ-Library-v0.5.0.apk` for Android 8.0 / API 26 or newer.

The application ID remains `com.weekssa.opraeqforuapp`, versionCode is 5, and v0.5.0 uses the same permanent Android signing identity as prior releases. Existing installations should upgrade in place without uninstalling or clearing app data.

## Everything from v0.4 remains

v0.5 retains the source-agnostic EQ Library foundation: output-specific My EQs, canonical OPRA/AutoEq/community/qualified-source catalog handling, General EQs, explicit new-EQ review without silent selection, Hide/Unhide, personal Equalizer APO / AutoEq PEQ import, safe Storage Access Framework ownership/currentness handling, UAPP/ToneBoosters conversion, and qualified TRN Black Pearl Direct Flash/Reset behavior.
