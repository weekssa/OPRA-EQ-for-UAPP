# v0.7.0 — draft, not released

Status: software implementation and release-candidate hardening are in progress on
`feature/v0.7-ew300-luna-high` / draft PR #23. No merge, publication, or public EW300 support
claim is authorized.

Scope is the exact SIMGOT EW300 DSP identity (`31B2:0111`, `LE XIAN`, `SIMGOT EW300 DSP`, HID
interface 3) through the existing capability-driven My DAC flow: five-band direct-Hz Peak EQ,
readback, capture, guarded Apply, one-Save Flash, Reset, reconnect-aware verification, and
privacy-safe readable/JSON operation evidence. Playback gain remains device state and is not part
of canonical captured EQs. Other device controls, unknown revisions, firmware, and VID/PID-only
matches remain unsupported.

Accepted historical evidence is recorded in `docs/EW300_VALIDATION_LEDGER.md`. The current branch
fixes a verified permission-flow race by blocking automatic reconnect until the Save send has
completed and by recording permission/Save/readback invariants. Exact signed candidate
`855364e8a9d758f12e7d2a48bdaf89f457e28070` passed the complete software, security, signing,
installation, upgrade/emulator, launch, accessibility, and release-polish gates, but the owner’s
Apply attempt stopped before any write because the editor mapped the EW300 global-gain baseline
incorrectly. Replacement source `8bb87aac689ce28b1e92e115a3f83f1b59ad1f65` corrects that mapping
and passed the complete replacement gate set. A follow-up source
`f41f985cb9f7a5d1622bc2e85ddfe5d14777e25d` blocks automatic reconnect after a pre-Save stop and
also passed the complete replacement gate set. The current source
`7035518b042a7b19c0495869cf247359ee27b4a2` additionally guards queued automatic reconnect at
invocation time and passed the complete replacement gate set. The one consolidated physical session in
`docs/EW300_DSP_HANDS_ON_CHECKLIST.md` remains outstanding for that exact candidate.
