# v0.7.1: Canonical Favorite resolution

This patch fixes canonical Favorites for catalog EQs whose effective catalog
product uses a retained legacy product identity. Favorites now resolve across
the current canonical headphone catalog source kinds while preserving the
selected canonical profile, revision, acoustic fingerprint, and source
references.

The correction changes compatibility product and vendor IDs only after the
effective catalog proves the exact alias and the displayed product and vendor
exist. Invalid, stale, ambiguous, or mismatched selections continue to fail
closed.

This is a library identity and persistence fix. It does not change EQ values, source-feed parsing, DAC protocols, or hardware behavior.

The compatibility rebase also preserves verified OPRA band-order provenance
from the profile-scoped canonical OPRA identity. Conflicting vendor/product IDs
across revisions remain untrusted. Regression coverage uses one
real canonical profile/revision sample per source ID currently present in
catalog profile references. Headphone samples exercise the shared alias path;
General EQ samples exercise their separate exact resolver. Adding an ingested
source requires a current sample and passing JVM/CI coverage before catalog
publication.

## Verification scope

The synthetic regression matrix covers catalog source kinds across three
headphone products. The real-source fixture separately covers every distinct
source ID in current canonical profile revisions, including two General EQ
sources. `DEVICE_CAPTURE` and `PERSONAL_IMPORT` remain in their separate local
saved-EQ flows. Source-specific feed parsers are not independently revalidated
by this resolver coverage.
